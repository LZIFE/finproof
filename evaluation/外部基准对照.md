# 外部基准与评分体系对照（v2.6.0）

日期：2026-10-25 · 目的：回答两个问题——①有没有**真实（非预埋）错误数据**可用于测评；②GitHub 上有没有**现成评分体系**可借用，把自制 2/1/0 口径升级为学界/业界认可的指标。

---

## 一、真实错误数据（按可用性排序）

### 1. Fin-Fact —— 唯一"真实错误 + 专业标注 + 开源可用"（首选）

- 仓库：https://github.com/IIT-DM/Fin-Fact（MIT 协议；2026-04 归档只读，数据仍可下载，另有 HF：`amanrangapur/Fin-Fact`）
- 内容：**3,562 条真实金融主张**，来自专业事实核查员的公开核查（含 Claim / Claim Label（supported/refuted 类）/ Justification / Evidence / Evidence href 等字段），覆盖多个金融板块。
- 用法——**外部真实性臂**：抽 50–100 条 claim + 证据链接直接喂给鉴融（联网模式），对照 Claim Label 算**一致率**。这直接回应"预埋错误是自己出的题、自己当裁判"的质疑：错误是真的、标签是专业核查员定的。
- 限制：英文；主张口径偏社交媒体帖文（非研报句式）；判定粒度是主张级三分类（非审计报告级）。

### 2. FinanceBench —— 真实报告 + 真实数字锚点（构造材料，非错误数据）

- 仓库：https://github.com/patronus-ai/financebench（10,231 问，开源精简版约 150 题 + 84 份真实 SEC 10-K/10-Q 文件，附证据串）
- 用法：用**真实文件里的真实数字**生成正确表述与扰动错误，替代合成 Y 公司锚点——数字全部真实可溯源，"证据包"就是原始 SEC 文件。适合做英文场景或混合场景套件。
- 限制：英文 SEC 文件；QA 形态，需自行改造为"报告审计"形态。

### 3. PHANTOM（NeurIPS 2025 D&B）—— 领域对标，暂不作数据源

- 论文：https://openreview.net/forum?id=5YQAo0S3Hm ；HF：`seyle/Phantom_Hallucination_Detection`
- 金融长上下文 QA 幻觉检测基准（query–answer–document 三元组，幻觉/正确二分类）。形态是 QA 检测而非报告审计，且无 GitHub 工具链；**引用价值 > 数据价值**——可在比赛材料中说明"金融幻觉检测是 NeurIPS D&B 级别的问题域"。

### 4. 中文真实错误源 —— 无现成数据集，但存在真实语料（高成本、高叙事价值）

A 股**年报/公告更正公告**（巨潮资讯可检索）与**交易所年报问询函**是真实世界的报告错误语料。构建"更正公告驱动套件"（爬取→对齐更正前后文本→标注错误类型）成本高，但若做成，是中文场景独一无二的实测数据。列为远期项。

### 5. FEVEROUS —— 评分方法可借，数据域不匹配

- 仓库：https://github.com/Raldir/FEVEROUS（87,026 条已验证主张，维基百科表格+文本证据）
- 数据域是维基百科，不作数据源；但其 **FEVEROUS Score（标签正确 + 证据精确匹配才给满分）** 与鉴融"[E##] 逐字摘录"理念同构，评分设计可引用。

## 二、可借用的评分体系（GitHub 现成）

### 1. ALCE citation precision/recall —— 对 [E##] 证据链最有针对性（首选）

- 仓库：https://github.com/princeton-nlp/ALCE（Princeton NLP，EMNLP 2023）
- 指标：**citation precision**（所引证据是否支撑该句）/ **citation recall**（该句所有主张是否都有证据支撑），自动评测用 **AutoAIS**（T5-11B NLI 模型），与人判一致率约 85%/78%。
- 接入：把鉴融审计报告的每条主张 × 其所引 [E##] 逐字摘录喂给 AutoAIS（或本地 NLI 模型），自动得**引用精确率/召回率**——"来源可核对"从自评变成第三方可复算指标。
- 落点：可作为第五维「来源权威性」之外的**报告级附加指标**（不改评分公式，只加披露）。

### 2. SAFE F1@K —— 检出指标的学界口径（低成本，立即接入）

- 仓库：https://github.com/google-deepmind/long-form-factuality（NeurIPS 2024）
- 指标：**F1@K = precision@K × recall@K**——长文拆原子事实、检索验证。
- 接入（零工具成本）：预埋错误集 = 金标准事实集，被测方反驳/问题清单 = 检出集，直接算 P/R/F1。与自制 2/1/0 并行报告：2/1/0 保留"部分检出"细粒度，F1@K 提供跨研究可比的硬口径。**第四轮与近容差轮的记录字段已加入。**

### 3. FEVER 三分类 P/R/F1 —— 判定映射的标准命名

- 鉴融六类结论 → FEVER 标准三分类映射：`SUPPORTED→SUPPORTS`；`REFUTED→REFUTES`；`INSUFFICIENT/UNABLE→NOT ENOUGH INFO`（PARTIALLY_SUPPORTED 按主判归并并单列计数；OPINION_OR_FORECAST 不参与，与"G 类不计入分母"一致）。
- 用途：对外材料可用"主张级三分类 F1（FEVER 口径）"这一标准表述，无需改造内部体系。

### 4. FActScore —— 方法论同构，用于对外命名

- 仓库：https://github.com/shmsw25/FActScore（EMNLP 2023）
- 鉴融"A–G 拆解 + 逐条判定"与 FActScore"原子事实分解 + 支持率"同构；对外可将报告级结果表述为"FActScore 式支持率"，增强学术可信度。

### 5. RAGAS / DeepEval —— 检索层质量（可选）

- 仓库：https://github.com/explodinggradients/ragas 、https://github.com/confident-ai/deepeval
- faithfulness / context precision / context recall 可评鉴融的**证据检索层**（找的证据对不对），但默认 RAG QA 场景，接入成本高于 ALCE；列为可选。

## 二·5、第二轮检索补充（2026-10-25 深夜：核查管线 / LLM 裁判 / 审计-agent 方向）

| 项目 | 是什么 | 对鉴融的 adoption |
|---|---|---|
| **Factcheck-GPT**（[yuxiaw/Factcheck-GPT](https://github.com/yuxiaw/Factcheck-GPT)） | 文档级核查管线：分解→去语境化→**check-worthiness 识别**→证据检索→判定 | 管线与鉴融同构；**借鉴点：check-worthiness 识别**（哪些主张值得查——鉴融目前全量拆解，长报告可作优先级信号，与"高风险优先"互补） |
| **OpenFactCheck**（[yuxiaw/openfactcheck](https://github.com/yuxiaw/openfactcheck)） | 统一核查框架，组件化：claim processor / retriever / **verifier / abstainer** | **借鉴点：abstainer（弃权者）组件化**——鉴融的 G 缺口/INSUFFICIENT 本质即 abstain，可对外表述为四组件架构（拆解器/检索器/判定器/弃权器）；其 factuality eval 模块可作未来自动裁判 |
| **G-Eval**（[EMNLP 2023](https://aclanthology.org/anthology-files/pdf/emnlp/2023.emnlp-main.153.pdf)，[DeepEval 内置](https://github.com/confident-ai/deepeval)） | LLM-as-judge：CoT 生成评审步骤→表单打分 | **借鉴点：裁判自动化**——目前测评裁判=人工主会话；P2 之后可引入 G-Eval 式自动裁判交叉校验人工评分（警惕 judge 偏差需双人复核） |
| **auditable / awesome-auditable-ai**（[yzhao062](https://github.com/yzhao062/auditable)） | 审计 AI agent 本身的开源方法库（事前配置审计/事中监控/事后失效定位） | 理念印证：鉴融的自检复核/AQS 即"审计 agent 自身被审计"的实现；其 failure localization 思路可启发"判定失败归因" |
| Receipt Auditor AI 等垂直审计 agent | 收据合规审计（解析→政策推理→异常→报告） | 场景不同（凭证合规 vs 报告事实核验）；**未发现成熟的"研究报告事实审计 agent"开源对标——鉴融的差异化定位成立**（答辩可用） |

## 二·6、第三轮检索补充（2026-10-26：自洽性/自我验证方向——设计印证）

| 发现 | 对鉴融的意义 |
|---|---|
| **Self-Confirmation Trap**（[Autonomous-Agents 综述收录](https://github.com/tmgthb/Autonomous-Agents)） | 学界明确指出同模型自我确认是陷阱——**直接印证复核档位设计**（异源 > 同源盲复核 > 自检〔机械层〕）；本包异源实测（C50 被第二双眼睛抓住 / C43 复核方自身出错）与该文献结论双向吻合 |
| **自我反思有效性研究**（[arXiv 2405.06682](https://arxiv.org/html/2405.06682v3)） | 纯 self-reflection 不可靠，**工具接地的批判（CRITIC 式）才有效**——学术镜像即"确定性判定归程序"：temporal/match/yoy 引擎子命令正是工具接地 |
| [LLM-as-a-Verifier](https://github.com/llm-as-a-verifier/llm-as-a-verifier) | 免训练细粒度验证反馈框架——未来裁判自动化的候选，当前无必改项 |
| [ICSFSurvey](https://github.com/iaar-shanghai/icsfsurvey) / [Awesome-LLM-Self-Consistency](https://github.com/SuperBruceJia/Awesome-LLM-Self-Consistency) | 内部一致性/自反馈综述——自检复核〔机械层〕的理论定位参考 |

**第三轮结论：无新增必改项。** 三轮检索（数据集→管线/裁判→自洽性）覆盖了能找到的全部相关方向；核心设计选择（确定性引擎、跨模型复核、诚实弃权）均与文献一致且已有实测。剩余差距全部为资源型（见主报告）。
