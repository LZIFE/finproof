## 一、页码体系确认（进入后续阶段前的统一约定）

| 项 | 约定 |
| -- | ---- |
| 金标准 `page` 字段 | **PDF 物理页码 `page_number`，从 1 开始**（即 PDF 阅读器显示页码） |
| 与解析层的对应 | PyMuPDF 索引为 0 基 `page_index`；`page_number = page_index + 1` |
| 本阶段 API/前端 | 默认展示与传参均使用 `page_number` |
| 现有金标准 | 已全部为该体系（构建时以 `doc[page-1]` 提取核对），无需迁移 |
| `printed_page_label` | 财报正文印刷页码无法可靠识别，统一记为 `null`（后续阶段可增强） |

**结论：现有金标准页码体系与 Phase 2 规定一致，无需迁移。**

## 三、金标准修正记录（复核发现并修正）

### 1. EVD-005 / EVD-006 / EVD-007 / EVD-008（CLM-005 / CLM-006 证据片段）

- **原内容**：`evidence_text` 为"其中：营业收入 456,451,731 407,149,600"与"减：营业成本 (335,989,528) (299,584,935)"
- **问题**：年报第 135 页合并利润表原始提取中，表格列间存在脚注引用单元格（如"四(48), 十八(3)"），上述含表头标签的片段在原始提取文本中**并非连续出现**（数值本身在该页真实存在）
- **修改后内容**：`evidence_text` 改为页面中实际连续的数字片段——`"456,451,731 407,149,600"` 与 `"(335,989,528) (299,584,935)"`（经空白归一化比对确认存在于第 135 页）
- **修改原因**：证据片段必须能在原始提取文本中逐字定位，保证可追溯性；表头标签含义保留在 `notes` 字段
- **涉及文件**：`data/demo/annotations/gold_evidence.json`
- **修改日期**：2026-07-31

### 2. CLM-003 原句修正（全量扫描发现）

- **原内容**：`original_text` = "归母净利润439.45亿元，同比增长14.03%"
- **问题**：研报原文中该句的增速为 38.02%（即 CLM-004 的错误表述），14.03% 并不出现在报告中——原句记录与报告不符
- **修改后内容**：`original_text` = "归母净利润439.45亿元"（报告原文片段，逐字存在）
- **修改原因**：金标准主张必须来自报告原文；14.03% 的正确增速保留在 `gold_verifications.json` CLM-003 的 explanation 中（由 439.45/385.37 亿复算得出），判定 SUPPORTED 不变
- **涉及文件**：`data/demo/annotations/gold_claims.json`
- **修改日期**：2026-07-31
