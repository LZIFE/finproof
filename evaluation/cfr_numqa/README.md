# CFR-NumQA · 中文财报数值链路跑分

**日期**：2026-10-26
**数据集**：CFR-NumQA（吉林师范大学，CC BY 4.0 数据 / MIT 代码）
**来源**：`github.com/fightvictory/CFR-NumQA` → `data/qa_seed.jsonl`
**规模**：1,016 题，覆盖 103 份 A 股年报（平安银行、万科A、美的、格力、五粮液、隆基、顺丰等）
**任务**：验证鉴融的确定性计算链路在**中文真实财报数据**上是否算对

## 为什么跑这个

此前所有验证都是英文（AnamnesisBench、FinanceBench）或自造中文材料。鉴融在真实中文 A 股场景的表现没有任何第三方证据。这个数据集的三个特点补上这个缺口：

1. **题目自带金标准操作数**（`meta.value` / `meta.values` / `meta.unit`），可纯机械评分；
2. **单位是真实写法**——"百万元"这种带"元"的复合单位、"（494.78）亿元"这种全角括号负数；
3. **含负基数场景**——亏损公司的同比，这是 A 股研报的高频雷区。

## 结果：1,016/1,016 = 100%

| 题型 | 题数 | 通过 | 验证内容 |
|---|---|---|---|
| extraction | 540 | **540/540** | 数值抽取 + 单位换算（含括号负数、全角括号、中文复合单位） |
| yoy_compare | 386 | **386/386** | 同比计算（含负基数：亏损收窄/扩大、转正） |
| cross_company | 90 | **90/90** | 两公司数值比较方向 |

## 这个 100% 暴露并修掉了两个真 bug

初次跑分是 381/386 和 509/540。两个缺口都不是边界情况，而是 A 股年报的常态。

### bug 1：负基数同比方向算反（5/386）

`yoy` 的分母用了带符号的 `previous`，而 SKILL 文档写的是 `|上年同期值|`——**代码与自身文档不一致**。

| 公司 | 2024 | 2025 | 业务含义 | 修复前 | 修复后 |
|---|---|---|---|---|---|
| 万科A 归母净利 | −494.8 亿 | −885.6 亿 | 亏损扩大 | +78.98%（错） | **−78.98%** |
| 隆基绿能 归母净利 | −86.2 亿 | −64.2 亿 | 亏损收窄 | −25.51%（错） | **+25.51%** |
| 隆基绿能 经营现金流 | −47.2 亿 | +43.6 亿 | 由负转正 | −192.26%（错） | **+192.26%** |

方向反了在审计里是致命的——"亏损收窄"被写成"负增长"，读者会得到相反的判断。修复：分母改 `abs(previous)`。

### bug 2：中文复合单位静默失效（31/540）

`UNIT_SCALE` 只有「百万」「十亿」，没有「百万元」「十亿元」。而真实财报写的是后者。

更危险的是 `UNIT_SCALE.get(unit, 1.0)` —— **不认识的单位按 1 倍处理，不报错**：

```
convert_to_yuan(179895, "百万元") → 179895      # 少了 1e6 倍
```

银行、保险类年报基本都以"百万元"计价，这个 bug 会让所有这类报告的数值核对整体错 100 万倍，而且**不会有任何警告**。修复：补全 `十万元/百万元/千万元/十亿元/百亿元/千亿元/万亿元`，共 7 个单位。

## 这个结果能证明什么、不能证明什么

**能**：鉴融的确定性计算链路在 1,016 道中文真实财报题上零错误，包括负基数和复合单位这两个英文基准永远测不到的场景。修复后的 7 个单位与 4 条负基数规则已进 108 项回归测试。

**不能**：这是"算得对不对"，不是"找得对不对"。题目把 `meta.value` 直接给了出来，省掉了"从年报哪一页哪个表找到这个数"这一步——那一步是模型的活，需要另设测试。所以 100% 不能解读为"鉴融能正确回答这 1,016 个问题"。

**也不能**：CFR-NumQA 的金标准本身可能有标注误差（题库由脚本从解析后的表格生成，未逐条人工复核）。不过 100% 一致意味着至少鉴融与它的口径完全对齐。

## 复现

```bash
cd evaluation/cfr_numqa
python3 run_bench.py     # 需要 qa_seed.jsonl（598KB，已随仓库）
```

原始数据获取（GitHub 直连不稳时用 codeload）：

```bash
curl -sL "https://codeload.github.com/fightvictory/CFR-NumQA/zip/refs/heads/main" -o cfr.zip
# 解压后取 CFR-NumQA-main/data/qa_seed.jsonl
```
