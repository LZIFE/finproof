# Fin-Fact 外部真实性臂 · 结果报告

日期：2026-10-25 · 数据：Fin-Fact（MIT，3,369 条真实专业核查主张）分层抽样 50 条（种子 42 可复现：20 true / 20 false / 10 NEI，剔除疑问句式与无证据链接条目后从 1,243 条池抽取）· 两臂同模型（GLM-5.3）、同宿主、均联网 · 裁判=主会话（与前三轮一致，持裁定密钥）· 全部原始输出存 `runs/`（jr_batch1-5.json / bl_batch1-5.json）

---

## 一、先说数据集的重要发现（影响一切解读）

**Fin-Fact 的 label 不能直接当句子级真值用**。它的 label 标注对象是【被核查的原始谣言】的真假，而 claim 字段常为否定式/疑问式标题。对 50 条样本逐条裁定后：

| 噪音类型 | 条数 | 例 |
|---|---|---|
| 极性翻转（否定/疑问式标题，label 与句子方向相反或错位） | 12 | C01"普京**没有**骂奥巴马"gold=false（指谣言假，句子为真）；C29"可口可乐**未**发售 KKK 瓶"gold=false |
| NEI 标注噪音（事实核查明确判 False 却标 NEI） | 4 | C35 死囚最后一餐（Snopes False）、C43 IRS 钓鱼邮件（Phishing bait） |
| **合计不可直接用于句子级评测** | **16/50 (32%)** | 裁定明细见 `adjudicated_key.json`（逐条含理由） |

因此主指标采用**裁定密钥**（句子级真值：true 29 / false 16 / mixed 2 / nei 3）；原始 label 口径的结果仅作附录（`eval_summary.json`，其数字无解释力）。

## 二、主结果（裁定密钥口径）

| 指标 | 鉴融臂（SKILL v2.6.0 全流程） | 裸提示基线 |
|---|---|---|
| **严格一致率** | 78.0%（39/50） | **92.0%（46/50）** |
| **软一致率**（部分支持/uncertain 计半分） | 88.0%（44/50） | **94.0%（47/50）** |
| **硬错误**（方向判反或对疑问句乱判） | **1 条**（C50，见下） | 2 条（C45 疑问句判真、C48 判 uncertain 而句子可判为真） |
| 疑问句如实说"无可判定" | **3/3** | 2/3 |
| mixed 类给出"混合"判定 | **2/2**（PARTIAL 恰为理想判定） | 0/2（uncertain，可接受但信息量低） |
| 编造 URL / 摘录 | 0 | 0 |
| 成本 | ~947 万 tokens，10 条/约 20 分钟 | ~493 万 tokens，10 条/约 8 分钟（**1.9×**） |

**两臂各自动错误明细（诚实披露）**：
- 鉴融唯一硬错误 C50（"时薪 $15 将摧毁至多 370 万岗位"判 OPINION_OR_FORECAST·依据已披露）：PolitiFact 判 False——CBO 中心估计是减 140 万，370 万系挑 2019 旧报告区间上限夸大。**按 SKILL 对抗性防御规则，所依赖基期数字被夸大本应单独判 REFUTED，此条暴露"G 类依据已披露"核查深度不足**——已记录为改进项。
- 基线两条硬错误：C45（"Two Buck Chuck 为何便宜"疑问句判 true）、C48（"帖文具误导性"——Snopes 证实帖文确属误导，句子可判真却收口 uncertain）。

## 三、v2.6.0 新能力在真实任务中的实测表现

1. **自检复核〔机械层〕**：批次 1、5 的子代理在无指示情况下主动执行并标注〔引擎重跑一致 · 摘录复读一致〕——零成本兜底层按设计生效。
2. **时序不可能**：C20（伪造电邮截图日期早于班加西袭击两个月）被点破"截图日期先于事件，时序不可能"——真实语料上首次命中。
3. **确定性引擎**：10 条数值主张全部〔引擎复算〕留命令轨迹，含 C39 相对差 0.237%<0.5% 的**舍入豁免精确应用**（判支持未误伤）与 C27 的 +2.5876%（支撑"基本停滞"的部分支持判定）。
4. **六类结论的粒度价值**：鉴融对 10 条"Mostly True 带限定"的主张给出 PARTIAL（软一致计分），每条附限定说明（如"57/62 县上升而非 all"）——二元判定会抹掉这层信息，这是"审计级产出"在真实语料上的形态。

## 四、结论（如实）

1. **"检出更多"在真实核查语料上同样不成立**：强模型裸提示对真实可检索主张的一致率（92%）高于鉴融严格口径（78%）——与三轮预埋报告结论方向一致。真实差异仍在产出层：证据链（每条附逐字摘录+可点击来源）、数值可复算（10/10 引擎轨迹）、疑问句/混合主张的诚实分类（3/3 与 2/2）。
2. **鉴融的硬错误率更低（1 vs 2）但严格一致率更低**——原因是六类结论对"Mostly True"一律不判 SUPPORTED，FEVER 式二分口径下吃亏；软口径差距收窄至 6pp。**对内改进项**：C50 类"依据已披露但依据本身失真"的 G 类主张应触发基期数字核查。
3. **Fin-Fact 可用作回归基准但需先过裁定**：32% 标签对句子级评测不可用；建议任何使用该数据集的工作先做极性裁定（本目录 `adjudicated_key.json` 可直接复用）。
4. 成本实测：真实联网核验场景鉴融为裸提示 1.9×（低于预埋报告场景的 5–7×，因主张短、无需全量拆解）。

## 五、方法边界（必须随结果一起读）

**答案可检索性**：两臂的证据高度依赖 Snopes/PolitiFact 原文，而这些页面的评级正是金标准来源——即两臂都能通过检索"读到答案"。因此本测评度量的是**"找到并正确应用专业核查结论"的能力**，不是脱离核查员的独立验证能力；两臂同享该便利，**臂间对照公平，但绝对一致率数字会偏乐观**，不可解读为独立核验准确率。

## 六、复现

1. 数据集（30MB，MIT）：`curl -sL -o finfact.json https://raw.githubusercontent.com/IIT-DM/Fin-Fact/b30387813734d4b461e6fcdd576feb819cc0bcbd/finfact.json`；抽样种子 42（过滤规则：陈述句式、40–300 字符、含证据链接，池 1,243 条）；批次输入 `batch_{jr,bl}1-5.json`（不含答案）。
2. 鉴融臂：子代理先 Read `finproof-verifier/skills/finproof-verification/SKILL.md` 再逐条核验（联网，允许读 evidence_links）；基线臂：同模型 general-purpose 子代理，仅一句"核实真假+理由+来源"。
3. 评分：`python3 eval_finfact_v2.py`（裁定密钥口径）；`python3 eval_finfact.py`（原始 label 口径，仅附录）。
4. 并发提示：本环境子代理并发上限 2，5 批需按 2 并行分波执行。
