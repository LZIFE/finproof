# 对抗性盲区与防御性检查（Adversarial Blind Spots）

> 来源：对 `backend/app/services/red_team/attack_generator.py` 的审计结论 + 本报告核验方法论的推论。
> 性质：**这是给专家自己的防御清单**，不是攻击教程。目的是让我们抓得住"看起来没问题"的错误。

## 一、为什么要这份清单

现有红队模块（`attack_generator.py`）只覆盖 5 种攻击，且**全部是粗粒度**的：

| 已覆盖攻击 | 手法 | 预期风险 |
|---|---|---|
| NUMERIC_HALLUCINATION | 数字 ×1.3 ~ 1.8 | 75 |
| PERIOD_CONFUSION | 期间整体替换（2025H1 → 2025Q2） | 70 |
| GROWTH_ERROR | 增长率 ×2.0 ~ 3.5 | 80 |
| UNSUPPORTED_STRATEGIC | 整句替换为夸大战略表述 | 65 |
| FORECAST_AS_FACT | 预测语态改为完成时 | 72 |

这些错得太明显——只要确定性复算在工作就能抓到。**真实报告里的错误不长这样。**

真实错误通常是：**数字对得上，含义不对；或者偏差小到落在容差内。** 下面五类就是红队没测、但真实场景高发的形态。

## 二、五类未覆盖攻击与针对性检查动作

### ① 披露舍入掩护下的明细偏差（SMALL_DEVIATION）

**形态**：真实值 4.38 亿写成 4.42 亿（+0.9%），或把"亿元保留两位"当作挡箭牌掩盖真实差异。

**危害**：这是造假与模型幻觉的**主要形态**（不是 1.8 倍那种）。容差一旦给宽，小幅偏差就会整片漏过。

**容差已量化（原为黑箱，本版明确）**：

| 复算类型 | 容差 | 超限 |
|---|---|---|
| 数值比对 / 累计转单季 / 比率 | **相对 0.1%** | → REFUTED |
| 增长率（同比/环比） | **0.5 个百分点（pp）** | → REFUTED |

**披露舍入豁免（唯一例外）**：偏差若**能由报告声明的舍入精度解释**（亿元保留两位、万元取整等），可判 SUPPORTED，但必须标 `[舍入差异 x%]` 并写出两个值。**豁免上限 0.5%**——超过 0.5%，无论能否用"舍入"解释，一律 REFUTED。

**强制检查动作**：

- 数值主张**不得只报"匹配/不匹配"**，必须写出：复算值 / 报告值 / **绝对差** / **相对差（%）**——通过与否都要写。
- 相对差 >0.1% 且**无法**由声明舍入精度解释 → REFUTED（不得因"差得不多"放行）。
- 引用"四舍五入"辩解时，必须**验证舍入能否解释该差值**：4.38 → 4.6（+5.0%）不能被任何常规舍入解释，属 REFUTED。
- 判定为 SUPPORTED 但相对差 ∈ (0.1%, 0.5%] 且可由舍入解释 → 标 `[舍入差异 x%]`，让用户自行判断。

> **变更说明**：本文件 v1.5.1 曾写「相对差 >2% 标 [微幅偏差]、>10% 不得判 SUPPORTED」。该阈值与引擎实际容差（**0.1% / 0.5pp**）**不一致**——按引擎口径，2% 的偏差早已超出容差、应为 REFUTED，不存在"带标记的支持"这一档。**本版已统一为引擎容差**，消除该矛盾。

### ② 口径伪装（SCOPE_SUBSTITUTION）——数值全对，含义错了

**形态**：
- "净利润 5 亿"实际用的是**扣非**口径
- "营收 120 亿"实际是**主营业务收入**而非营业总收入
- "Q2 净利"实际是 **H1 累计**
- "公司营收"实际是**母公司**而非合并报表

**危害**：数字能复算、来源能追溯，**只有口径这一层能拦**。期间混淆红队测了，口径混淆没测。

**强制检查动作**（落点在八步链第 5 步 `unit_scope_match`）：

- 判 SUPPORTED 前，必须**显式写出双栏对照**：`报告口径` vs `证据口径`，两者一致才放行。
- **禁止空口径通过**：不得在"还没确认口径"的情况下，因为数字对得上就直接判 SUPPORTED。口径未知 = `unit_scope_match` 未通过 → INSUFFICIENT_EVIDENCE。
- 四类高危口径逐项过：归母↔扣非、营收↔主营、单季↔累计、合并↔母公司。
- 若发现报告与证据口径不一致，**即使数值完全相等**，也必须判 REFUTED 或 PARTIALLY_SUPPORTED，并在修改建议里写明应改的口径。

### ③ 单位/币种伪装（UNIT_SCALE）

**形态**：438 亿写成 438 万；人民币数值套用港币/美元；百分比与百分点混用（pp vs %）。

**危害**：数字**字符串相同**，单位不同，语义量级差万倍。

**强制检查动作**：

- 每条数值主张必须**显式确认单位**（元/万元/亿元/百万元）并完成量级换算后再比较。
- 单位缺失且无法从上下文推断 → INSUFFICIENT，不自作主张补默认值。
- 跨币种必须写明汇率来源与取值日期；未标注汇率来源的一律标 **[单位未确认]**。
- **pp 与 % 必须区分**：毛利率"提升 3%"与"提升 3pp"含义不同，不得混判。

### ④ 编造因果（SPURIOUS_CAUSALITY）——两件事都真，因果是编的

**形态**："毛利率提升 3pp，主要由原材料降价推动"——毛利率确实升了，原材料确实降了，**但两者因果关系并无证据**。

**危害**：E 类（因果）主张**纯靠模型判断，没有确定性引擎兜底**。"数字归程序"这条铁律在因果面前完全失效。

**强制检查动作**：

- 因果型主张（E 类）默认门槛提高：**要求证据中出现机制性表述**（"由于/受益于/带动/导致"等）或**可比期初值变动方向一致**，否则降为 PARTIALLY_SUPPORTED 或 INSUFFICIENT。
- **禁止把"时间先后"当"因果"**：两件事同向变动不等于前者导致后者，审计报告必须点明这一区别。
- 量化归因类（"贡献 X pp"）必须能复算：分项变动之和应等于总变动，算不平即为 REFUTED 或 PARTIALLY_SUPPORTED。
- 在主张卡中明确区分：**[事实成立] / [因果成立]**，不得混为一谈。

### ⑤ 引用错配（QUOTE_MISALIGN）

**形态**：引用的原文真实存在，但**支撑不了该主张**——用 2024 年的数据支撑"2025 年增长"，用行业数据支撑公司结论，用母公司披露支撑子公司主张；**极端形态是时序不可能**：所引来源的覆盖期间早于数据所属期间（"据 2025 年年报第 12 页"引用 2026H1 数据）。

**强制检查动作**：

- 引用必须三对齐：**来源文件 + 页码/章节 + 报告期**，缺一视为错配。
- **时序不可能（最高优先，无需证据闭环）**：所引来源的**覆盖期间早于数据所属期间**（如"据 2025 年年报"披露 2026H1 数据），该来源在逻辑上**不可能**包含该数据——这是纯逻辑判定，**不需要找到真实出处即可判 REFUTED（引用一致性·时序不可能）**。实测教训：只查"页码在不在证据包"会把它错收进 G1"源文件缺失"，漏掉真正的判定点。G1 不得收容时序不可能——补传源文件改变不了逻辑矛盾。
- 用相似期间（相邻年度/相邻季度）支撑的，必须在主张卡标注 **[期间近似]** 而非默认通过。
- 用行业/同业数据论证本公司结论的，必须标注该数据并非本公司披露。
- 错配不影响"来源本身的真实性"，但直接影响该主张的结论：按 INSUFFICIENT 或 PARTIALLY_SUPPORTED 处理；**时序不可能形态按 REFUTED 处理**（逻辑上已可判定，非证据缺口）。

## 三、三类针对鉴融自身的元攻击

这三类不攻击报告，**攻击的是我们的判定机制本身**——必须靠显式约束来防。

### A. 检索逃逸——让对的证据找不到

**手法**：用生僻表述写指标（"母公司拥有人应占溢利"代替"归母净利润"），BM25 与规则召回都捞不到 → 判 INSUFFICIENT。

**后果**：报告**不会被判错，只是"没核出来"**。攻击者不需要让数字正确，只需要让它查不到。实测归因里 81% 的失败本就在这条路上。

**防御**：
- 判 INSUFFICIENT 时，若报告用语与常见财务表述差异明显，标注 **[疑似检索逃逸]** 而非中性收口。
- 聚焦再搜索必须覆盖同义/异形表述（含港式表述、英文财报惯用语）。
- 并入「需用户自行核验清单」，明确告知"此项我们没找到，不等于它没问题"。

### B. 诱导"证据不足"——付费墙逃逸

**手法**：把争议数字全部引向 Wind / 付费研报库等不可达来源 → 专家标 G2 放弃。

**后果**：报告**既没判错也没判对，蒙混过关**。

**防御**：
- G2 必须在自核清单中**显著列出**，不得与其他缺口一样轻描淡写。
- 报告级摘要须写明："本报告中 N 条主张因来源不可达未能闭环，**未闭环 ≠ 通过**"。
- 不得因为"没找到反证"就倾向判 SUPPORTED。

### C. 表面合规刷分——引用好看但结论不对

**手法**：大量引用权威来源、格式规范，但核心数字有误。

**后果**：FinProof Score 里**来源权威性（15%）+ 引用一致性（20%）衡量的是"引用好不好看"，不是"结论对不对"**。一份引用规范但数字有误的报告，可能比引用随意但数字正确的得分更高。

**防御**：
- 每次输出 Score 时必须附一句固定警示：
  > FinProof Score 反映**证据链质量与引用规范**，不代表结论正确性。引用规范的报告仍可能存在数字或口径错误；请结合「反驳/部分支持」条数与「需用户自行核验清单」一并判断。
- Score 高于 85 但存在 REFUTED 主张时，必须在摘要首行点名该矛盾。

## 四、复合攻击

红队只测单一攻击，**真实造假是组合拳**：

> 小幅篡改（5%）+ 口径模糊（不明写是否扣非）+ 包装成预测（"我们预计约 4.6 亿"）

每一项单独都过得了关，合起来才是完整的错误。

**强制动作**：对 HIGH / CRITICAL 风险的主张，三项同查——**数值偏差是否超容差（0.1% / 0.5pp）？口径是否显式确认？是否被包装成预测以规避核验？**

被包装成预测不等于免责：若预测所依赖的基期数字有误，仍须就该基期数字单独判 REFUTED，并注明"预测结论基于有误的基期数据"。

## 五、风险引擎自身的两点局限（判读时须知）

- **clamp 抹平区分度**：0.9% 的偏差与 80% 的严重造假，只要都判 REFUTED，风险分可能都被压到接近 100，**无法体现轻重**。因此主张卡的"相对差（%）"字段比风险分更能反映严重性——**两个数都要给**。
- **CRITICAL 是联合判定，不是纯引擎输出**：引擎的分数映射只输出 LOW / MEDIUM / HIGH 三级。**CRITICAL（极高）** 需满足 `risk_score ≥ 90` **且** 该主张是核心结论的直接承重依据（投资建议/核心估值/收入利润主指标），属"引擎分 + 业务承重判断"。表达"极高风险"时**必须写明理由**，不得只给标签（口径见 `scoring-spec.md` §6.3）。

## 六、审计报告中的落点

审计输出必须包含一段「**对抗性抽查**」（即使无问题也要写"未发现"），列出本次已核查的高危形态：

```
对抗性抽查：
- 明细偏差：检查 N 条数值主张，相对差超容差（>0.1%，或增长率 >0.5pp）的 M 条
            （逐条列出 复算值/报告值/相对差%；标 [舍入差异 x%] 的 Y 条）
- 口径伪装：归母↔扣非 / 营收↔营业总收入 / 单季↔累计 / 合并↔母公司 —— 已核验 X 项 / 发现 Z 处不一致
- 单位与币种：已确认单位 N 条 / [单位未确认] M 条 / pp 与 % 混用 Z 处
- 编造因果：E 类主张共 N 条 —— [因果成立] X 条 / [仅事实成立] Y 条
- 引用错配：来源 + 页码/章节 + 报告期三对齐 → 发现 Z 处不对齐（其中时序不可能 N 处——来源期间早于数据期间，无需证据闭环即判）
- 元攻击：[疑似检索逃逸] M 条 / G2 付费墙缺口 N 条（未闭环 ≠ 通过）
- Score 提示：FinProof Score 反映证据链质量与引用规范，不代表结论正确性
```
