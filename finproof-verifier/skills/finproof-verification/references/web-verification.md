# 联网核验协议（Web Verification Protocol）

本专家在受理时**先判定用户的核验范围要求**，再决定要不要联网。是否联网不由专家自行决定，而由用户要求驱动：用户可能只想"按我上传的材料判断"，也可能要"联网核对真实披露"。本协议定义范围判定门、需求判定门、权威来源优先级、检索流程与联网操守。

> **核心原则：优先用 WorkBuddy 自带联网搜索，不依赖用户额外连接任何服务。** 联网搜索是 WorkBuddy 平台原生能力，无需用户登录或配置。金融数据 MCP（Tushare / 东方财富妙想 / 腾讯自选股）仅作**可选增强**——若会话已连接则并用，未连接则完全不影响核验。

---

## 一、范围判定门（Scope Gate）：先问用户要哪种核验

**受理第一步：判断用户要求的核验范围。** 这不是专家替用户做的决定，而是看用户怎么说、或主动问一句。

### 两种核验模式

| 模式 | 触发（用户表述） | 行为 |
|---|---|---|
| **本地模式（Local-only）** | "只按我上传的内容判断" / "不联网" / "看内部一致性/自洽" / 只关心报告本身逻辑 | 仅依据用户上传的文件 + 本地 FinProof 证据索引判断；**不联网**。对查不到外部佐证的，标"证据不足（未联网）"，不尝试联网。 |
| **联网模式（Local + Web）** | "验证真实性" / "联网核对" / "对照真实披露" / "查真实数据/公告" / "和真实财报对一下" | 在本地基础上，用 WorkBuddy 联网搜索对照真实披露核对准确性（见下文需求判定门 + 检索流程）。 |

### 受理时怎么做

1. **鼓励上传本地证据**：无论哪种模式，都请用户把**待审研报**发来；若用户手上有对应的**年报/公告/招股书原文**，一并上传——本地证据越全，核验越强（本地模式尤其依赖此）。
2. **从用户表述识别模式**：用户明确说"只按上传的"/"不联网" → 本地模式；说"验证真实性"/"联网核对" → 联网模式。
3. **歧义时问一句（不超过一次）**：若用户没说清，开场用一句话确认范围，例如：
   > "你希望我：① 仅依据你上传的文件判断（不联网）；② 上传文件 + 用 WorkBuddy 联网搜索核对真实披露？默认我按你上传的内容先核，需要联网再开。"
   给出默认建议：若用户只发了研报、没发源文件，建议选 ②（能抓出更多"与真实披露不符"的错）；若用户连源文件一起发了，① 已很强。
4. **绝不擅自联网**：未确认进入联网模式前，不调用任何联网搜索；本地模式全程不联网。

## 二、需求判定门（Need Gate）：仅联网模式下生效

进入**联网模式**后，再判断是否真的需要发起搜索（避免对本地已能覆盖的主张浪费检索）：

1. **本地证据能否覆盖全部主张？** 用户上传的文件 + 本地 FinProof 证据索引已能逐项核对（数字可复算、口径可对照、期间可对应）→ **直接跳过联网**，照常输出本地结论。
2. **缺口是否确属外部/实时数据？** 只有被判「证据不足」且缺口类型是以下之一，才算"确需联网"：
   - 特定公司的财报数字（营收/利润/资产负债等）不在本地证据中；
   - 最新行情、实时报价、当日涨跌幅；
   - 尚未纳入本地索引的最新定期报告/临时公告。
   - **首轮联网补证后仍判「证据不足」的，进入第六节「聚焦再搜索」做 2–3 轮换词换源重试，穷尽后才最终保留「证据不足」**——不要把"首轮没搜到"直接当结论。
3. **纯方法论 / 观点 / 历史科普类报告**，或证据已自洽的报告 → **永不触发联网**。

判定结果处理：
- **无需联网**：照常输出本地结论。
- **确需联网**：调用 WorkBuddy 联网搜索（见下）补证，结论标注「联网证据」。
- **联网不可用**（会话无 WebSearch/WebFetch 能力）：如实说明"当前会话无联网搜索能力"，退回本地证据链并标"证据不足"，**不假装已搜索、不提示用户去连任何 MCP**。

## 三、首选：WorkBuddy 内置联网搜索（WebSearch / WebFetch）

WorkBuddy 原生提供两类联网工具，是核验的**默认且首选**外部数据通道：

- **WebSearch**：按关键词检索全网，定位权威一手来源的链接（交易所公告、公司 IR、年报 PDF、权威财经数据库条目等）。
- **WebFetch**：对具体 URL 抓取并提取正文/PDF 内容，读取与主张**同口径、同期间**的原始数值。

调用顺序建议：
1. 用 **WebSearch** 以 `公司名 + 股票代码 + 指标 + 报告期`（如 `美的集团 000333 2025 营业收入 年报`）检索，优先命中交易所官网 / 公司 IR / 巨潮·互动易等一手页面。
2. 对命中的一手链接用 **WebFetch** 读取，提取原始数值并记录 `来源名称 + 完整 URL + 抓取时间`。
3. 多个一手来源互相交叉验证；媒体仅作线索，不作为一手证据。
4. 所有联网数值须与「本地证据」区分标注，并注明数据时点。

> 金融数据 MCP（Tushare / 东方财富妙想 / 腾讯自选股）**仅在此通道之外作可选增强**：若会话已连接对应 MCP，可并用其结构化一手财务接口作二次交叉验证；未连接则忽略，绝不提示用户登录或连接。

## 四、权威来源优先级（一手 > 二手 > 未知）

1. **交易所官网公告 / 定期报告原文**：上交所、深交所、港交所、北交所、SEC EDGAR、公司招股书/年报/季报 PDF 原文。
2. **公司投资者关系（IR）页面**：年报、业绩快报、临时公告原文。
3. **权威财经数据库与终端**：Wind、Bloomberg、Choice、东方财富、通联数据、巨潮/互动易（已连接的金融 MCP 即属此类一手接口，但非必需）。
4. **主流财经媒体**（证券时报、财新、华尔街见闻、第一财经等）：仅作线索，不作为一手证据，引用需二次溯源。
5. **博客 / 论坛 / 社媒 / 营销号**：不采用，除非仅用于"市场传言"类主张的溯源标注。

## 五、操作流程

1. **判定范围（Scope Gate）**：识别/询问用户要本地模式还是联网模式；鼓励上传研报与（如有）源文件。
2. 明确待核验主张：`指标 / 数值 / 期间 / 口径 / 实体`。
3. **本地核验（两模式共有）**：对照用户上传文件 + 本地索引，亲自按 `calc-engine.md` 复算，给出六类判定与证据链。
4. **（仅联网模式）需求判定门**：本地证据已覆盖 → 跳过联网；确需外部数据 → 进入第 5 步。
5. **（仅联网模式）WorkBuddy 联网搜索 + 聚焦再搜索**：WebSearch 定位一手来源 → WebFetch 读取提取同口径同期间数值；已连 MCP 可并用。复算比对，冲突判 REFUTED 并附联网来源。**首轮补证后仍「证据不足」的主张，进入第六节「聚焦再搜索」：换查询词（全称/简称/代码/英文品名）、换权威源（年报原文PDF→互动易/IR→权威媒体→行业价格库→行情聚合）、收窄到精确期间、子公司查"主要控股参股公司"段，重试 ≤2–3 轮；每轮记录 query+来源+命中，命中即收口复算，穷尽无果才保留「证据不足」并透明列出检索尝试。**
6. 结论显式标注「本地证据」或「联网证据」，给出来源 + 数据时点（URL + 抓取时间，或 MCP 工具名 + 调用时间）。
7. **输出前链接复验（v2.5.0 起，定稿必做）**：证据清单定稿前，对**全部联网证据 URL 逐条发起访问**（WebFetch / 浏览器），把复验状态写进证据条目「链接」字段——`〔复验：可达 / 重定向 / 不可达(状态码) / 未复验(原因) · YYYY-MM-DD〕`。规则：
   - **可达**：正常打开，与抓取时一致 → 维持等级。
   - **重定向**：跳转到新地址仍可达 → 维持等级，注明跳转目标。
   - **不可达**（403 / 404 / 超时 / 付费墙拦截）：**不删除证据**（保留原抓取时间与逐字摘录——那仍是当时真实取到的），但证据等级**降一档**并在条目显著标注；该证据若支撑 REFUTED/关键结论，优先换源补证一次。
   - **未复验**：本地模式 / 检索预算不足 / 无联网能力 → 如实标〔未复验（原因）〕，**不得谎称已验**。
   - 复验访问**计入联网检索 40 次预算**；预算紧张时优先复验**问题项引用的与 S/A 级**证据，其余标未复验并在报告说明。

## 六、聚焦再搜索（Focused Re-Search）

**目的**：联网模式下，首轮 WebSearch/WebFetch 后仍判「证据不足」的主张，**不立即放弃**，而是针对该主张的**不确定原子事实**做聚焦再搜索——换查询词、换权威源、至多 2–3 轮，穷尽后才定论。把「证据不足」从"首轮没搜到"升级为"已尽力检索仍无佐证"：既提高覆盖率，又保持诚实（不把没搜到的说成"对"）。

**触发条件**
- 主张经八步判定落入「证据不足」，且处于**联网模式**、会话具备 WebSearch/WebFetch 能力；
- 或主张「部分支持」但含一个**具体未确认子项**（如某细分价格点位、某子公司净利）。

**不触发**：本地模式（直接标"未联网"）；纯观点/预测类（归"观点或预测"）；已确认付费墙/无源可查且记录过限制。

**重构查询战术（先拆原子事实）**
把不确定点拆成 `实体 + 指标 + 期间 + 单位`，再按以下顺序换词重试：
1. **换词表述**：全称↔简称↔股票代码（"永和股份"↔"永和"↔"605020"）；中文名↔英文/别名（"R32"↔"二氟甲烷"↔"refrigerant R32"）。
2. **换权威源（按优先级递进）**：
   - 公司**年报/中报/季报 PDF 原文**（cninfo）→ 用 WebFetch 直接读原文，查"主要控股参股公司""经营情况讨论"等章节；
   - 公司**投资者关系 / 互动易**（上交所 e 互动、深交所互动易）→ 搜"邵武永和 净利润"等问答；
   - **权威财经媒体**（证券时报 / 中国证券网 / 财联社 / 新浪财经）→ 线索与二次溯源；
   - **行业价格库 / 商品资讯**（若可检索：百川盈孚、隆众、上海有色网、生意社）→ 价格点位类主张的优先源；
   - **行情聚合**（东方财富 / 同花顺 iFinD）→ 补充交叉验证。
3. **收窄到精确期间**：把"2026 上半年"拆成"2026Q1""2026 年 3 月""2026 年一季度"等更细粒度再搜。
4. **子公司 / 细分数据专用**：搜 `子公司全称 + 营收/净利润`，并回到母公司年报"主要控股参股公司"表；不要只搜母公司合并口径。

**轮次与记录**
- 每个证据不足主张最多 **2–3 轮**聚焦再搜索；每轮记录：`轮次 / 查询词 / 来源类型 / 命中(✓ 部分✓ 未命中✗) / 备注`。
- 一轮命中即停止该主张再搜索，进入复算比对；结论若改为「支持/反驳/部分支持」则更新证据链。

**检索硬预算（必须遵守，不得静默超支）**
- **单次核验联网检索总量 ≤ 40 次**（含首轮补证、全部聚焦再搜索轮次与定稿前链接复验访问）。
- 达到预算时：**停止新增检索**，把剩余未检索的主张列入「**未检索清单**」，连同已达成的结论一并交回用户，并明确写"以下 N 条因检索预算用尽未做联网核验，未闭环 ≠ 通过"。
- **禁止**：因预算紧张而静默减少轮次、跳过某条主张而不说明、或把"没搜"写成"搜了没找到"。
- 优先分配预算给**高风险主张**（影响核心结论的优先）。

**收口规则**
- 穷尽 2–3 轮仍**无任何一手/二手佐证** → 保留「证据不足」，但审计报告必须列出**已尝试的检索**（query + 来源 + 命中情况），让缺口透明、可追溯。
- **缺口必须分类（G1–G4）并给出用户动作**：保留「证据不足」时，按以下归类并写明用户下一步：
  - **G1 源文件缺失**：对应披露文件用户未上传，无一手文本可核 → 用户上传文件后重跑，或确认仅做内部一致性核验。
  - **G2 检索不可达**：付费墙（Wind/部分研报库）、未索引页面、离岸/Pre-IPO 披露分散，2–3 轮仍取不到 → 用户凭已授权数据源（券商终端）或一手渠道自核；专家不伪造。
  - **G3 非公开/未披露数据**：细分口径、未披露子公司经营数据、内部假设，原始披露中本就不存在 → 属报告方自有假设，用户确认依据是否充分、是否标注「内部估算/未审计」。
  - **G4 提取失败（OCR 不可识别）**：源 PDF 为扫描件、表格转图片、编码乱码，pypdf 未抽出可读文本 → **先按第七节「内置 OCR 路径」由专家自行完成识别**（渲染 + 本地 OCR + 多模态视觉读取），识别结果须复核；加密/损坏/模糊到手写级别仍不可信，才归 G4 → 用户提供更清晰文本版/可复制层 PDF，并附已尝试的 OCR 手段。
  - 每条「证据不足」标 `[Gx] 原因 + 用户动作`；审计末尾汇总成「需用户自行核验清单」。
- **绝不**因"再搜一轮还没命中"就伪装"已确认"或强行判"支持"——那会制造假阳性，比漏判更危险。
- 遇付费墙 / 机器人拦截 → 标注"需授权数据源，未检索"，不计入"已尽力"。

## 七、内置 OCR 路径（G4 提取失败的处理）

**原则：G4 不是"直接甩回用户"，而是先由专家自己完成 OCR 识别。** WorkBuddy 环境内置可用的 OCR 能力（零配置、无需登录外部服务），按以下顺序处理扫描件 / 图片表格 / 乱码 PDF（已实测：PyMuPDF 渲染 + tesseract `-l chi_sim` 可识别中文页）：

1. **文本直抽（快路径）**：pypdf / pdfplumber 抽取文本层；数字型 PDF 直接可用，跳过 OCR。
2. **渲染 + 本地 OCR**：PyMuPDF（fitz）把每页渲染为 PNG（150–300 dpi），用本机 tesseract（`-l chi_sim`，已验证中文可用）识别为文本，再按 calc-engine 复算。
3. **多模态视觉读取**：把渲染出的页面图片交给带视觉能力的模型逐页阅读（等价于"自带 OCR"），核对关键数字与表格结构；识别结果标注"经视觉读取"。
4. **表格结构恢复**：财务表格优先用 pdfplumber `extract_table` 恢复行列结构；OCR 纯文本仅作兜底，避免表格串行。
5. **可选增强**：若会话已连接文档解析类 MCP（TextIn xParse / 扫描全能王），可并用作增强 OCR；未连接则完全不影响，绝不提示用户去连。
6. **OCR 结果复核**：识别出的关键数字必须与上下文交叉验证（如 合计 = 分项之和、同比可复算），并标注"OCR 识别，可能有 ±1 字符误差"。

**仍失败才归 G4**：加密 PDF（需密码）、文件损坏、或图像质量过低（模糊/旋转/手写）导致 OCR 结果不可信 → 归 G4，用户提供更清晰文本版，同时附上**已尝试的 OCR 手段**（渲染 dpi、tesseract 语言、是否视觉读取）。

## 八、操守（铁律）

- **范围由用户定**：未确认联网模式前绝不擅自联网；本地模式全程不联网。
- **能力先行**：仅当联网模式且会话确实具备 WorkBuddy 联网搜索（WebSearch/WebFetch）能力时才检索；无能力时如实说明，退回本地证据链，**绝不假装已搜索、绝不提示用户去连接外部服务**。
- **必须溯源**：每条联网证据标注 `来源名称 + 完整 URL + 抓取时间`；区分「本地证据」与「联网证据」。
- **链接须复验**：报告定稿前逐条访问证据 URL 并缀复验状态（见第五节第 7 步）；不可达降一档、保留原摘录；未复验如实标注，**不得把"写得出 URL"当成"链接活着"**。
- **严禁编造**：绝不编造搜索结果、URL、数值或"据说已核实"；命中不了就标"证据不足"。
- **标注时滞**：联网数据可能与本地演示数据存在版本/时点差，必须注明数据时点（如"截至抓取日 XXXX-XX-XX"）。
- **受限处理**：遇付费墙 / 机器人拦截导致抓取失败时，说明限制，改走本地证据或建议用户提供文件，不强行臆测。
- **MCP 不强制**：金融数据 MCP 未连接时正常用联网搜索核验，绝不因"没连 MCP"而卡住或索要登录。
