# 演示用例、评测与经验教训（demo / evaluation / lessons）

> 来源：`data/demo/company_selection.md`、`docs/finproof_mvp_scope.md`、`docs/final_submission_report.md`、`docs/current_error_attribution.md`。

## 一、演示公司选择（Midea Group 美的集团，000333，深交所主板）

候选三家均为大型消费/家电/食品饮料/新能源（不选银行保险证券），实测 9 份 PDF 全部文本型、可提取、保留页码：

- **美的集团**：四大业务分部（智能家居/新能源及工业技术/智能建筑科技/机器人与自动化）+ 海外收入分地区披露 → **错误构造空间最大**（可覆盖数字/计算/时间/累计单季/指标口径/引用错配/证据不足/因果过度推断/单位币种 ≥8 类）；理解难度低（家电龙头）；2025 年报+一季报+半年报同属 2025 会计年度，天然支持 `Q2 = H1 − Q1` 累计转单季演示；文件为原始披露版本。
- 五粮液：评委理解成本最低，但分部与业务事实类主张受限，部分文件为"更新后"版本。
- 宁德时代：高增长故事适合同比/环比错误，但一季报净利润关键词因表格单元格拆分提取有小瑕疵。

**最终选定美的集团**：错误构造空间最大、理解难度最低、提取质量实测最优、数据新鲜且口径自洽、来源记录干净。备选顺序：五粮液 → 宁德时代。

## 二、金标准设计（Gold Standard）

- 1 家真实公司 + 真实年报/季报/半年报 PDF + 预埋 8~12 处错误的研报 + `gold_claims.json`。
- 金标准须**同时包含三类样本**（缺一不可，否则评测口径失真）：
  1. 预埋错误条目（测错误召回率）
  2. 正确条目（测误报率）
  3. 证据不足条目（测拒答准确率）
- 每条含：`claim_id / original_text / verdict / error_type / planted_value / correct_value / source_page / note`。
- 数字必须来自真实披露，错误必须逐条记录——**禁止编造演示数据**。

## 三、预埋错误类型（≥6 类，实际覆盖 ≥8 类）

数字错误 · 计算错误（同比算错）· 时间错误（过期/错期）· 口径错误（累计当单季、归母/净利润混用、单位/币种混淆）· 引用错配 · 证据不足 · 因果过度推断 · 预测事实化。

## 四、评测指标与目标（见 risk-governance-audit.md）

错误召回率 ≥90% · 误报率 <10% · 证据匹配率 ≥85% · 拒答准确率 ≥80% · 真实 E2E Acc≥0.70 / Macro-F1≥0.60 / Coverage≥0.65。

**目标 vs 实测对账（v2.5.0 补，必须如实）**：
- E2E 三项（Acc / Macro-F1 / Coverage）有实测且达标（见第五节）。
- **错误召回率 ≥90% 是设计目标，提交评测未公布、也未随包留存其实测值**——只公布了 per-class F1（REFUTED 0.71）。F1 由精确率与召回率共同构成，**不得引用 F1 暗示召回达标**；在校准数据补齐前，错误召回率一律按**未验证**表述。
- 误报率 / 证据匹配率 / 拒答准确率同理：无随包实测值的，不得作为"已达标能力"对外表述。

## 五、提交版实测与经验教训

- **实测（Phase 23.11 Gate，43 claims）**：Acc 0.7442 / Macro-F1 0.7264 / Coverage 0.7442，均达提交目标；相对 Phase 23.9 基线 +0.1163。
- per-class F1：SUPPORTED 0.88 / OPINION_OR_FORECAST 1.0 / REFUTED 0.71 / UNABLE_TO_DETERMINE 0.67 / PARTIALLY_SUPPORTED 0.67 / **INSUFFICIENT_EVIDENCE 0.43**（最弱项）。
- **主导瓶颈 = 检索覆盖缺口**：失败 case 多数 →`INSUFFICIENT_EVIDENCE`；Phase 23.37 错误归因中 Retrieval failure 占 81%。
- **改进纪律（铁律）**：禁止修改 gold、禁止硬编码 case、禁止绕过 Gate、禁止调整 reranker weight（已验证无效）；正确方向是 Retrieval Expansion（扩 fact 覆盖、公司+metric+period 联合检索、query decomposition）。
- **关键创新点**：strict scope 归因 + 主表利润证据严格恢复，稳定修复归母/扣非净利润类误判。
- **演示高光时刻（须可复现）**：①累计当单季被 `Q2=H1−Q1` 推导反驳；②同比重算不一致判反驳；③证据不足因果结论审慎判"无法判断"；④每条证据带文件与页码可原页核对。

## 六、这些评测数据的正确用法与边界（v2.0.0 新增）

**可以怎么用**：
- 作为 FinProof Score 的**校准依据**——说明"这套判定逻辑在已知对错的样本上表现如何"，而不是凭感觉打分（见 `scoring-spec.md` 第十节）。
- 作为**能力自证**：Acc 0.7442 / Macro-F1 0.7264 / Coverage 0.7442 均达标；相对 Phase 23.9 基线 +0.1163。

**不能怎么用**（避免过度宣称）：
- ❌ **不得表述为"通用准确率 74%"**。该数字来自**内部金标准**：1 家真实公司 + 预埋 8–12 处已知错误的研报，共 **43 条**主张，样本量有限。
- ❌ **不得说"已通过第三方评测"**——这是**自建金标准上的自测**；且**样本外部有效性弱**：1 家公司 / 43 条 / 预埋错误（错误类型由设计者选定），**不可外推**到其他公司、其他报告风格、真实（非预埋）错误。
- ❌ 不得隐去弱项。
- ❌ 不得把"错误召回率 ≥90%"的目标说成实测结果（见第四节对账）。

**必须主动披露的弱项**：
- `INSUFFICIENT_EVIDENCE` 的 F1 仅 **0.43**，是最弱项；根因是**检索召回缺口**（错误归因中 Retrieval failure 占 **81%**，16/21 为正确证据未进候选池）。
- **这恰好解释了为什么"聚焦再搜索"与"G1–G4 缺口分类"是本体系的核心设计**——体系知道自己最弱的地方在哪，并把这一点显式告诉用户（而不是硬撑覆盖率）。

**评测纪律（不可违反）**：
- 不修改金标准标签、不硬编码 case、不绕过证据门、不通过调 reranker 权重刷分（均已验证无效）；正确方向是**检索扩展**（扩展 fact 覆盖、公司+metric+period 联合检索、query decomposition）。
- 金标准必须同时含**错误/正确/证据不足**三类样本，缺一即评测口径失真。
