# FinProof 核验操作手册（鉴融）

本 Skill 是鉴融的**可执行操作层**。`agents/finproof-verifier.md` 定义角色与流程；本文件定义**具体怎么算、怎么判、怎么打分**。

> **本文件内的规则是自足的最小集，可直接执行，无需先读 references/。**
> `references/` 提供细则与背景；**遇到需要精确公式、容差表、评分推导、检索战术时，必须读取对应文件**，不要凭记忆。

## 零、执行前必做五件事

1. **定范围与档位（Scope Gate）**：本地模式（仅按上传内容，不联网）还是联网模式（+ WorkBuddy 内置 WebSearch/WebFetch）？由**用户**决定，不由你自定；表述不清时只问一次。未确认前绝不联网。**同时确认运行档位**：完整档（默认）或快速档（见 0.1——用户明示"快速过一遍/先粗查"，或报告 ≤10 页且用户只求硬错误时可用）。
2. **验证据是否够用（Need Gate，仅联网模式）**：本地证据已覆盖全部主张 → 跳过联网。
3. **声明降级**：无 shell 时 `bin/finproof_calc.py` 不可用，复算退化为模型内算——**必须逐条标注〔心算估算，未经引擎复算〕**，不得以相同置信度输出。有 shell 时必须调引擎。
4. **边查边记来源**：审计报告的每条结论都要挂 `[E##]` 证据编号并给出**可点击链接 + 抓取时间 + 逐字摘录**（格式见 `citation-format.md`）。因此**检索/读文件时就要把 URL、时间、页码、原文片段记下来**——事后补记必然遗漏或失真。**取不到链接就如实标原因，绝不编造。**
5. **确认复核通道与运行信息（v2.5.0 起）**：① 查明当前宿主是否提供**子代理/第二模型**调度能力（用于第六节独立复核）；② 记录当次运行的**模型名、核验模式、时间**——写入报告基本信息（复现性声明：数值复算可复现，拆解与语义判定由模型产出、两次运行可能不同）。

### 0.1 运行分档（v2.6.0 起：完整档 / 快速档）

鉴融完整流程的成本是裸提示的 5–7 倍（实测 52 万 vs 8 万 tokens），**长报告与深度审计值得，短报告快查可降档**：

| | 完整档（默认） | 快速档 |
|---|---|---|
| 触发 | 默认 | 用户明示"快速过一遍/先粗查"，或报告 ≤10 页且用户只要硬错误 |
| 主张拆解 | 全量 A–G + 编号 | 全量 A–G + 编号（**不省**） |
| 判定链 | 八步链全走 | **三项硬检查**：数值复算（引擎）＋ 口径双栏 ＋ 引用三对齐（**含时序不可能**）；八步链中的证据可用性/实体/指标/期间匹配仍走（它们是三项硬检查的前提），语义完整度与 E 类因果深查可缩 |
| 对抗性抽查 | 五类形态 + 三类元攻击全查 | 机械项全查（偏差/口径/单位/引用）；E 类编造因果与元攻击抽查**可缩**，报告注明"快速档未深查" |
| 独立复核 | 第六节全协议 | 缩至：问题项全量自检复核（机械层）；支持项抽样与评分复算可免 |
| 方法论加载 | 先读完整 SKILL.md | **只读本目录 `LITE.md`（轻量执行卡，v2.6.1 起自足）**；需要完整评分推导/HTML 报告/分批审时再回读本文件对应节 |
| 输出 | HTML 完整报告 | 纯文本精简版（九段结构不省、字段不省，主张卡仅问题项） |
| 报告标注 | — | 基本信息必须标〔快速档〕并列出省略项；评分仍输出，但须声明"快速档评分：语义层覆盖低于完整档" |

**快速档省的是流程，不是纪律**：容差表、判定来源标记〔引擎复算〕、G 类依据披露标注、G1–G4 缺口分类、"未闭环 ≠ 通过"、不编造来源——一律照旧。**快速档发现 ≥1 条 REFUTED 或 CRITICAL 风险项时，建议用户重跑完整档**（写进报告末尾建议行）。

## 一、主张拆解（A–G 七类）

| 类型 | 说明 | 核验重点 |
|---|---|---|
| **A 原始数字** | 直接陈述的数值 | 数字/单位/量级/期间/口径 |
| **B 计算型** | 含同比·环比·比率等推导 | 取两期数据重新算 |
| **C 口径型** | 涉及单季/累计、归母/扣非等 | 披露的是哪种口径 |
| **D 业务事实** | 定性业务结论 | 是否有披露支撑（市占率、客户结构、产能等） |
| **E 因果型** | 归因结论 | 原文是否支持所引原因、机制性表述 |
| **F 比较型** | 同业/对标比较 | 对标对象、指标、期间、口径是否可比 |
| **G 预测观点** | 前瞻/主观判断 | 标为观点，核查是否披露依据，不判真假；**逐条标注「依据已披露 / 依据未披露」** |

商业分析报告高频类型：市场规模与增速（A/B）、竞品对标（F）、商业模式归因（E）、门店/用户/产能等经营指标（A）、战略判断（G）。

**拆解纪律**：只提可独立核验的主张；复合主张必须拆开；增长率必须绑定指标与期间；观点/预测/因果必须正确归类（G 类不得判真假）。**编号纪律（v2.5.0）**：主张 `#1、#2…` 一律按**原文出现顺序**编号（可复现性要求）；"高风险优先"只决定**审阅与输出的先后**，不得重排编号。

**G 类输出纪律（v2.6.0 起硬规则）**：
1. **依据披露必须显式**：每条 G 类主张的结论行必须标注**「依据已披露」**（同时列出依据的证据编号）或**「依据未披露」**——不得静默归入"不判真假"了事；"依据未披露"的 G 类主张进「需用户自行核验清单」（G3 非公开数据/内部假设）。
2. **确定性语境的预测 = 预测事实化，进问题项**：前瞻表述若带"已无悬念 / 确定性强 / 板上钉钉 / 无虞 / 必然达成 / 胜券在握"等**确定性措辞**，视为把预测包装成事实陈述——结论仍为 OPINION_OR_FORECAST（G 类不判真假的规则不变），但**必须列入「审计结论」问题项**，问题写「预测事实化：确定性表述但依据未披露/不足以支撑确定性」；档位行的问题项计数含此类。所依赖的**基期数字若有误，仍须就基期单独判 REFUTED**（复合攻击规则）。
3. **「依据已披露」不免责——依据本身须核（v2.6.0 补，源自 Fin-Fact 实测教训）**：披露了测算依据的 G 类主张，须对**依据里的数字与来源**做核查（数值复算 + 追溯一手来源）；若依据失真（如引用区间上限冒充中心估计、旧报告数字冒充最新、来源不支持所引数值），该主张**进问题项**，问题写「依据失真：披露的测算依据与一手来源不符（{{差异}}）」——不得因"依据已披露"直接放行。

## 二、确定性复算（容差是硬规则，不是感觉）

### 2.1 容差表（来自引擎实现，不得放宽）

| 复算类型 | 容差 | 超限判定 |
|---|---|---|
| 数值比对、累计转单季 | **相对 0.1%** | `numeric_match=False` → **REFUTED** |
| 同比增长率、环比增长率 | **0.5 个百分点（pp）** | 超出 → **REFUTED** |
| 比率（毛利率/净利率/费用率/占比） | 相对 0.1% | 超出 → **REFUTED** |

**披露舍入豁免（唯一例外）**：偏差若**能由报告声明的舍入精度解释**（如亿元保留两位、万元取整），可判 SUPPORTED，但必须标 `[舍入差异 x%]` 并写出两个值。**豁免上限 0.5%**，超过 0.5% 无论能否用舍入解释，一律 REFUTED。

> 注意：任何数值主张**无论判定通过与否**，都必须写出 `复算值 / 报告值 / 绝对差 / 相对差%`。这是对抗性防御的硬要求——只看"匹配/不匹配"会漏掉明细。

**判定来源标记（v2.5.0 起硬规则，可溯源）**：每条数值主张的复算结论必须标注判定来源——
- 〔引擎复算〕：有 shell 时经 `bin/finproof_calc.py` 计算。**审计轨迹须保留引擎命令与输出**（如 `yoy --current 2.8 --previous 2.49 → 12.4498%`），这是"数字归程序"的运行证据，不得只写结论。
- 〔心算估算，未经引擎复算〕：降级时的既有标注。

**引擎覆盖率 `N_e / N_v`**：报告基本信息公开"数值主张中经引擎复算的条数 N_e 及占比"。该数不计分，仅溯源——它同时暴露非财务/低数字密度场景下引擎杠杆的真实水平（见第二节"通用数值复算"与附录口径披露）。

**N_e 统计口径（v2.6.0 起固定，消除跨轮次歧义）**：N_e **只计"实际调用了引擎、且审计轨迹留有命令与输出"的数值主张**——逐字一致但没跑引擎的不算，跑了没留轨迹的不算。免引擎仅两种情形且必须逐条标注：
- 〔逐字一致，免引擎〕：报告值与证据值**完全一致**（同数值、同单位、同量级），无须复算——计入 N_v、**不计入 N_e**；
- 〔心算估算，未经引擎复算〕：无 shell 降级——计入 N_v、不计入 N_e。

公开 N_e/N_v 时随附一句本口径（如"N_e=18/19；另 1 条逐字一致免引擎"），使不同轮次的覆盖率可比。

### 2.2 核心公式

```
同比增长率(%) = (本期值 − 上年同期值) / |上年同期值| × 100%
环比增长率(%) = (本期值 − 上一期值)   / |上一期值|   × 100%
Q2 = H1 − Q1 ;  Q4 = FY − Q1 − Q2 − Q3 ;  H1 = Q1 + Q2
毛利率(%)   = (营业收入 − 营业成本) / 营业收入 × 100%
净利率(%)   = 净利润 / 营业收入 × 100%
费用率(%)   = 某项费用 / 营业收入 × 100%
业务占比(%) = 分部收入 / 总营业收入 × 100%
CAGR(%)     = (末期/初期)^(1/年数) − 1
EPS = 净利润 / 总股本 ;  ROE = 净利润 / 平均净资产 ;  资产负债率 = 总负债 / 总资产
单位换算：1 亿元 = 1e8 元 = 10000 万元 ; 1 万元 = 1e4 元
```

**通用数值复算（非财务报告同样适用）**：占比、增长率、总和一致性（分项之和 = 合计）、时间序列推算（年均、复合）、单位/币种换算、百分点(pp)与百分比(%)的区分。

**精确计算**：有 shell 时调用引擎（参数名已实测校核，勿臆造）。

```bash
P=skills/finproof-verification/bin/finproof_calc.py
python3 $P yoy      --current 35.87 --previous 19.09            # 同比增长率 → 87.8994%
python3 $P qoq      --current 32 --previous 28                 # 环比增长率
python3 $P quarter  --h1 60 --q1 28                            # 累计转单季 → Q2 = 32
python3 $P match    --claim 4.38 --claim-unit 亿元 --evidence-yuan 439314000
python3 $P margin   --revenue 100 --cost 68                    # 毛利率 → 32%
python3 $P margin   --revenue 100 --segment-revenue 31.6       # 业务占比
python3 $P cagr     --end 35.87 --start 6.79 --years 3         # → 74.1622%
python3 $P convert  --value 35.87 --unit 亿元                  # → 3,587,000,000 元
python3 $P extract  --text "2025年营业收入35.87亿元"            # 抽取结构化数值
python3 $P period   --text "2026年上半年"                       # 期间归一化
python3 $P temporal --source "2025年年度报告" --data "2026年上半年"   # 引用时序检查 → IMPOSSIBLE（时序不可能，判定归程序）
python3 $P eps / roe / debt / cashdiff --help                  # 其余子命令
```

> **`match` 的容差**：引擎内置默认 `0.001`（0.1%）。如需临时放宽（例如已确认披露舍入较粗）显式传 `--tolerance 0.005`，**并在主张卡中说明放宽理由**。

> **引擎与后端的一致性提示（v2.7.1 已对齐）**：`backend/app/services/verification/base.py` 的 `VALUE_TOLERANCE` 已由 0.005 修正为 **0.001**（backend 984 项测试全绿零回归）；`numeric_verifier.py` 的 docstring 同步修正（其曾声称收紧到 0.1% 但代码仍为 0.005，属文档-代码分歧，已消）。注意：`evidence_retrieval/engine.py` 的 0.5% 为**检索候选预过滤**（有其回归原因），非权威判定口径。本 Skill 的 `bin/finproof_calc.py` 仍为唯一权威（42 项回归测试）。

## 三、八步判定链（不可跳步）

1. `evidence_availability` 证据可用性 — 无证据 → INSUFFICIENT
2. `entity_match` 实体匹配 — 主体不对 → INSUFFICIENT
3. `metric_match` 指标匹配 — 指标不对 → INSUFFICIENT
4. `period_match` 期间匹配 — 期间不对 → INSUFFICIENT
5. `unit_scope_match` 单位与口径 — 口径不对 → INSUFFICIENT
6. `numeric_calculation` 数值复算 — **冲突 → REFUTED（语义不得翻案）**
7. `semantic_completeness` 语义完整度（0–1）— <0.8 → PARTIALLY_SUPPORTED
8. `verdict_mapping` 结论映射 — forecast → OPINION_OR_FORECAST

**守卫**：`numeric=REFUTED` 时，无论语义给什么，**保留 REFUTED**。`numeric=SUPPORTED` 且语义不完整 → 可降为 PARTIALLY_SUPPORTED。

## 四、六类结论

| 结论 | 触发 |
|---|---|
| **SUPPORTED 支持** | 证据直接支持主体/指标/期间/单位/口径/数值，在容差内 |
| **REFUTED 反驳** | 证据给出冲突事实、错值、错期、错单位、相反方向 |
| **PARTIALLY_SUPPORTED 部分支持** | 多组成部分中部分成立、关键部分缺失，或证据只支持较弱表述 |
| **INSUFFICIENT_EVIDENCE 证据不足** | 既不能证明也不能反驳（**不得**把解析失败归入此类） |
| **OPINION_OR_FORECAST 观点或预测** | 预测/展望/主观判断，不判真假；**须标注「依据已披露 / 依据未披露」**；确定性语境的预测按「预测事实化」进问题项（见第一节 G 类输出纪律） |
| **UNABLE_TO_DETERMINE 无法判断** | 材料缺失或不可判定 |

优先级顺序：`REFUTED > SUPPORTED > PARTIAL > INSUFFICIENT`（是取舍顺序，不是等级）。

**判定校准（v2.6.1 起，对齐专业核查"Mostly True 计真"口径）**：核心主张成立、仅有次要限定（边缘时点、精度、个别措辞）→ 判 **SUPPORTED** 并附 `[限定：…]` 标注，不得因次要不精确降级 PARTIAL；**PARTIAL 仅用于关键组成部分缺失或与证据方向冲突**。数值主张不适用本校准——一律走容差表（数字守卫优先）。目的：与 PolitiFact/Snopes 的 Mostly True→true 分档一致，避免语义层的过度保守（Fin-Fact 外部臂实测教训：8 条 Mostly True 被判 PARTIAL，拉低严格一致率 14pp）。

## 五、对抗性防御（每次必做，不是可选项）

常规检验只能拦住"明显的错"。以下五类必须逐项过一遍，结论写进审计的「对抗性抽查」段落：

1. **披露舍入与明细偏差**：每条数值主张写出 `复算值/报告值/相对差%`；相对差 >0.1% 且无法由舍入解释 → REFUTED。
2. **口径伪装**：判 SUPPORTED 前必须双栏写出 `报告口径` vs `证据口径`。四类高危：归母↔扣非、营收↔营业总收入、单季↔累计、合并↔母公司。**口径未确认即判 INSUFFICIENT，禁止"数字对得上就放行"。**
3. **单位/币种伪装**：显式确认量级（元/万元/亿元）、币种与汇率来源、pp 与 % 区分。单位无法确认 → INSUFFICIENT。
4. **编造因果**：E 类须有机制性表述或可比期初值；**禁止把"时间先后"当"因果"**；归因类须可加总核对（分项之和 = 总变动）。主张卡须区分 `[事实成立]` / `[因果成立]`。
5. **引用错配**：来源 + 页码/章节 + 报告期**三对齐**；使用相邻期间须标 `[期间近似]`。**时序不可能检查（无需证据闭环）**：所引来源的**覆盖期间早于**数据所属期间（例："据《2025 年年度报告》第 12 页"支撑 **2026H1** 数据——2025 年报在逻辑上不可能披露 2026 上半年收入），属**纯逻辑即可判定**的引用错配 → 直接判 **REFUTED（引用一致性·时序不可能）**并注明"来源期间早于数据期间，无需证据即可判定"；**G1"源文件缺失"不得收容此类问题**——补传源文件也改变不了时序不可能。此检查是引用三对齐的**独立必做项、先于页码可核验性判断执行**——不得以"页码无法核验/来源存疑"替代时序判定（v2.6.0 第四轮实测教训：run1 曾因走页码核验路径漏判）。**有 shell 时必须走引擎判定**：`temporal --source … --data …` → IMPOSSIBLE/COVERED/PARTIAL/UNCLEAR（v2.6.2 起，纯逻辑判定归程序，不再依赖模型自觉；UNCLEAR 时才退回语义判定）。

**三类元攻击**（针对判定机制本身）：
- **检索逃逸**：报告用语生僻（如"母公司拥有人应占溢利"）导致查不到 → 标 `[疑似检索逃逸]`，不得中性收口。
- **诱导证据不足**：争议数字引向付费墙 → G2 须显著列出，并声明「**未闭环 ≠ 通过**」。
- **表面合规刷分**：引用规范但结论错 → 输出 Score 时**必须附固定警示**（见第八节）。

**复合攻击**：HIGH/CRITICAL 风险主张做三项同查——偏差是否超容差、口径是否显式确认、是否被包装成预测规避核验。**被包装成预测不免责**：若所依赖的基期数字有误，仍须就该基期单独判 REFUTED。

**时点漂移三档（行情/实时类主张，v2.6.2）**：核验日 ≠ 报告时点是常态（第四轮实测：PE 在快照日为真、核验日为假，两臂同误判）。按三档处理，**不得拿核验日数据直接判历史主张反驳**：
1. **期间内匹配**：主张绑定明确历史期间（"2026H1 净利"）→ 一律按该期间披露判定，与核验日无关。
2. **快照漂移**："当前/最新"类行情数据（市值/股价/PE）→ 以**最接近报告撰写日的可考快照**为证据并标〔快照时点 YYYY-MM-DD〕；仅能取到核验日数据且超容差时**不得判 REFUTED**——标〔时点漂移：按核验日差异 x%，需按报告日快照复验〕，归 PARTIAL/INSUFFICIENT 并入自核清单。
3. **无法锚定**：报告未写时点且推不出期间 → 要求补时点（G1 动作），不猜。

详见 `references/adversarial-blindspots.md`。

## 六、独立复核——异源第二双确认（v2.5.0 起必做）

**问题**：同一模型既拆解主张、又下判定、又给来源定级、又打分——自评闭环。**对策**：全部问题项判定 + 抽样的支持项判定，交给**另一个判断者盲复核**。完整协议见 `references/independent-review.md`。

1. **复核范围**：全部问题项（反驳/证据不足/部分支持/无法判断/预测事实化——G 类标记性问题项）**逐条复核**；支持项抽样复核 `max(3, ⌈10% × N_d⌉)` 条（按风险分降序抽）；**评分复算**——复核方按 `scoring-spec.md` 公式重算总分，核对五维分子/分母与主张清单的对应（机械核对）。
2. **盲复核**：只给复核方**主张原文 + 证据逐字摘录 + 复算数字**，**不给主审结论与理由**——防止锚定。
3. **异源优先**：宿主提供子代理/第二模型调度时，用**与主审不同的模型**复核（示例：主审 GLM-5.3 → 复核 GLM-5.3-Flash，经子代理发起）。异源复核显著削弱"同模型同盲区"风险。
4. **同源兜底**：无第二模型时，用**同模型冷上下文盲复核**（新会话/清空上文重新判定），标注〔同源复核，削弱有限〕。
5. **自检复核（机械层兜底，v2.6.0 起；零成本，尽量永远做）**：连冷上下文也开不了时，输出前对**每条 REFUTED 与全部扣分项**做机械自检——① **重跑引擎命令**：逐条重新执行该主张的 `finproof_calc.py` 命令，核对两次输出一致；② **复读证据摘录**：把主张所引逐字摘录与源文件/来源原文再比对一遍（防"摘录与原文不符"的事实性错误）；③ **核对统计口径**：扣分清单的数字与统计口径表对得上。报告标注〔自检复核：引擎重跑 N/N 一致 · 摘录复读 N/N 一致 · 口径核对 ✓〕。**边界必须如实写明**：自检复核只防机械性事实错误（算错、抄错、对不上），**不能**替代语义层面的独立判断——不得写成"已经复核"或省略"机械层"限定。异源/同源复核可用时自检层**叠加其上**（成本近零，仍值得做）。
6. **如实降级**：连自检复核也无法做（无 shell 且无源文可复读）→ 报告独立复核段写「本次未经独立复核 + 原因」。**不得把没做的复核伪装成做过**。
7. **分歧处理**：复核与主审不一致时**逐条披露**，不静默采纳任一方——主审结论保留（其证据链等级与引擎轨迹可查），**除非复核指出主审证据链中的事实性错误**（摘录与原文不符、复算数字错误等）——此时必须回查原料，错了就改并在「独立复核」段记录修正；其余分歧写进报告「独立复核」段，交用户裁决。自检复核发现不一致时同理：回查原料，错了就改，并在标注中如实计数。

**报告落点**：审计报告新增「独立复核」段（对抗性抽查之后）：复核方式（异源模型名 / 同源盲复核 / 自检复核〔机械层〕+ 计数 / 未复核+原因，可组合——如"异源 + 自检层"）· 复核范围 · 一致/分歧计数 · 分歧明细。

## 七、缺口分类与用户自核清单

保留「证据不足」时，必须归类并给出用户动作：

| 缺口 | 含义 | 用户动作 |
|---|---|---|
| **G1 源文件缺失** | 对应披露未上传 | 上传后重跑该主张 |
| **G2 检索不可达** | 付费墙、未索引、离岸/Pre-IPO 分散披露 | 凭已授权数据源自核；**未闭环 ≠ 通过** |

## 八、FinProof Score（完全透明，可复算）

### 8.1 五维与权重

| 维度 | 权重 | 计算对象 | 满分条件 |
|---|---|---|---|
| **可判定率**（历史名「证据覆盖率」） | 25% | 闭环主张 / 全部可判主张 | 全部主张有证据闭环 |
| **数字与计算准确性** | 25% | 1 − 数值类错误占比 | 无数值类 REFUTED |
| **引用一致性** | 20% | 1 − 引用错配占比 | 引用均三对齐 |
| **来源权威性** | 15% | 加权平均证据等级分 | 全部主张由 S 级证据支撑 |
| **时间与口径一致性** | 15% | 1 − 期间/口径问题占比 | 无期间错配与口径混用 |

### 8.2 每维打分公式（0–100）

```
可判定率          = 闭环主张数 / 可判主张数 × 100
数字与计算准确性  = max(0, 100 − 数值类错误占比 × 100 × 2)      # 1 条错扣 2 倍权重份额
引用一致性        = max(0, 100 − 引用错配占比 × 100 × 2)
来源权威性        = 加权平均证据等级分（S=100 / A=70 / 其他=40 / 未注明=0）
时间与口径一致性  = max(0, 100 − (期间错配数 + 口径问题数) / 可判主张数 × 100 × 2)

FinProof Score = 0.25×可判定率 + 0.25×准确性 + 0.20×引用一致性 + 0.15×来源权威性 + 0.15×时间口径
                （加权求和使用未取整的各维分值，最后四舍五入到整数；展示时各维保留一位小数、
                  加权贡献保留两位小数。先各自取整再加权会产生累积误差，明确禁止——与 scoring-spec.md 一致）
```

> 「可判主张数」= 总主张数 − 观点/预测类（G 类不计入分母，因为无从判真假）。
> 每条扣分必须能追溯到**具体主张编号 + 具体理由**，禁止无解释扣分。

> **口径披露（必须随分数一并告知用户）**：本维历史名「证据覆盖率」，v2.5.0 起更名**可判定率**（公式/口径/历史分数不变）——闭环口径含「支持 / 反驳 / 部分支持 / 无法判断」，因此**一份错误较多、但都能被判定（REFUTED）的报告，可判定率可以是 100**。它衡量"我们能否判定"，**不衡量"证据是否充分、来源是否可靠"**（后者由「来源权威性」维度承担）。
> **已知局限（待定夺，勿自行改动）**：「无法判断」被计入闭环、而「证据不足」不计入，二者边界重叠（都无法判定结论），当前口径会**系统性高估可判定率**。改动它会改变历史分数与金标准校准，故暂按现状执行，仅如实披露。

### 8.3 分数必须附带的结构（透明化强制要求）

输出 Score 时**必须一并输出**：
1. **五维明细**：每维的原始观测值（分子/分母）→ 得分 → 加权贡献；
2. **扣分清单**：每条扣分对应的主张编号、错误类型、扣分依据；
3. **等级判定**：按总分给出档位（见下），**档位行必须带问题项计数与"分数≠正确性"句**；
4. **固定警示**：Score 反映证据链质量与引用规范，**不代表结论正确性**；**且不同报告的 Score 不可横向直接比较**（准确性与可判定率的分子/分母都随该报告自身的主张总数变化：40 条里错 1 条扣分远小于 4 条里错 1 条）；
5. **自评声明**：本分为**专家自评**，非第三方认证；参考校准见 `references/scoring-spec.md`；
6. **口径披露**：说明「可判定率」（历史名「证据覆盖率」）衡量"能否判定"（闭环含 REFUTED），不衡量证据是否充分；来源权威性仅占 15%——**数字自洽但来源等级普遍偏低的报告仍可能拿到"优"**，须据此解读；
7. **弱来源警示（触发时）**：S+A 级证据占比 < 50% 或来源权威性 < 60 → 证据等级分布处显著标注「⚠ 弱来源依赖」（见 scoring-spec.md §3.4）。

### 8.4 分数档位

| 档位 | 区间 | 含义 |
|---|---|---|
| 优 | 90–100 | 证据链完整，无实质性问题（若仍有 REFUTED，须在首行点名矛盾） |
| 良 | 75–89 | 个别瑕疵，不影响核心结论 |
| 一般 | 60–74 | 存在影响局部结论的问题，需修订 |
| 差 | <60 | 存在影响核心结论的问题，不建议直接使用 |

**档位行强制格式**：`{{分数}} / 100 · {{档位}}——问题项 N 条（反驳 x / 证据不足 x / 部分支持 x / 无法判断 x / 预测事实化 x）；分数衡量证据链质量与引用规范，不代表结论正确性`。

### 8.5 主张级风险分（与总分不同，勿混用）

```
risk_score = 基准分(按结论) + 重要性 + 置信度项 + 证据质量项 + 预测加分 → clamp 到该结论区间
```

| 结论 | 区间 | 基准分 |
|---|---|---|
| REFUTED | 80–100 | 90 |
| INSUFFICIENT / UNABLE | 60–90 | 75 |
| PARTIALLY_SUPPORTED | 40–70 | 55 |
| SUPPORTED | 0–20 | 10 |

| 调整项 | 算法 |
|---|---|
| 重要性 | HIGH **+8** / MEDIUM **+4** / LOW **+0** |
| 置信度 | `(confidence − 0.5) × 24`；REFUTED/INSUFFICIENT/UNABLE 只加不减，SUPPORTED 只减不加 |
| 证据质量 | 数值类核验 eq=1.0 / 语义类 0.6 / 其他 0.3；REFUTED 加 `(eq−0.6)×12`；INSUFFICIENT 加 `max((0.6−eq)×12, 0)` |
| 预测类 | **+15** |

等级映射：`<30 LOW` / `30–65 MEDIUM` / `>65 HIGH`；**CRITICAL（极高）**：风险分 ≥90 **且** 该主张是核心结论的直接承重依据（如投资建议/核心估值/收入利润主指标）——CRITICAL 是"引擎分 + 业务判断"的联合判定，必须显式说明理由。

**报告整体风险** = `0.5 × max(主张分) + 0.5 × mean(非 SUPPORTED 主张分)`。

> 局限声明：`clamp` 会抹平区分度（5% 偏差与 80% 造假可能都被压到同档）。因此**主张卡的"相对差%"比风险分更能反映严重性**——两个数都要给。

详见 `references/scoring-spec.md`（含逐步算例）。

### 8.6 审计质量分 AQS（v2.7.0 起，与 FinProof Score 并列，勿混用）

**问题**：FinProof Score 度量**被审报告**的证据链质量——一份烂报告被审得越好（REFUTED 越多），准确性维扣分越多，分数反而低（实测：6 处错误全抓的审计只得 71–72 分）。用户看到"71 分·一般"容易误解为"审计没做好"。

**对策**：并列输出第二个分数——**审计质量分 AQS（Audit Quality Score，0–100）**，度量**这次审计自身的过程质量**，五维全部机械可算（无主观项）：

| 维度 | 权重 | 计算 |
|---|---|---|
| 主张覆盖 C | 30% | 已判定主张数 / 全部拆解主张数（分批未完成时如实 <100） |
| 引擎复算率 E | 25% | N_e / N_v（N_v=0 纯定性报告按 80 计，同准确性维惯例） |
| 证据可核性 V | 20% | 四必填完整的问题项 / 全部问题项（"依据未披露（无证据可挂）"如实标注亦计完整） |
| 复核完成度 R | 15% | 异源 100 / 同源盲复核 80 / 自检复核〔机械层〕60 / 未复核 0（叠加取最高档） |
| 链接复验率 L | 10% | 已复验 URL / 全部联网证据 URL（本地模式：L 权重并入其余四维，AQS=(0.30C+0.25E+0.20V+0.15R)/0.90） |

`AQS = 0.30×C + 0.25×E + 0.20×V + 0.15×R + 0.10×L`，四舍五入取整。档位同 FinProof（优 ≥90 / 良 75–89 / 一般 60–74 / 差 <60）。

**输出要求**：① 基本信息与档位行并列展示（`FinProof Score 71/100 · 一般 ‖ 审计质量 AQS 94/100 · 优`）；② 附五维明细（每维分子/分母 → 得分 → 加权贡献），推导透明度与 FinProof Score 相同；③ **固定警示（逐字）**：AQS 衡量审计过程质量，FinProof Score 衡量被审报告的证据链质量——两分独立解读，不可互相替代（好审计审烂报告 = AQS 高 + FinProof 低，这是正常且正确的组合）。规格与算例见 `references/scoring-spec.md` §十一。

## 九、输出结构（固定）

> **输出格式**：审计报告**默认输出为单文件 HTML**——内联 CSS、无外部依赖、双击即开；结论色彩编码、`[E##]` 锚点跳转、评分可点开、证据清单与长主张卡用 `<details>` 折叠。**纯文本降级**：环境无法渲染/保存 HTML 时回退为等价纯文本（字段完全一致，仅去色彩/折叠/锚点），不得省略必填字段。
> **三条硬规则**：① **标题从简、不加序号前缀**（"报告基本信息""报告健康度"）；② **问题前置**——「错误（反驳）」与「找不到支撑材料（证据不足）」集中进「**审计结论**」，紧随基本信息；③ **只报问题项**——核验通过（支持）的主张**不逐条展开**，只在审计结论末尾给一句计数；正文不写客套话、不复述公式全文。
> 完整 HTML 骨架（含 76 分算例）与降级纯文本模板见 `references/audit-report-template.md`。

```
报告基本信息
   报告名 · 页数/主张数 · 核验模式 · 运行档位（完整档 / 快速档，快速档须列省略项） · 核验时间 · 证据来源统计 · 计算方法（含降级声明）· 检索次数
```

### 9.1 证据引用硬规则（可核对性）

**每条主张都必须挂 `[E##]` 编号，每个编号在证据清单中都有完整出处。** 没有可核对来源的结论，不配写进报告。

- **编号**：`[E01]`…按首次出现顺序；同一证据支撑多条主张时复用编号。
- **联网证据必填**：来源名称 + **完整 URL** + 抓取时间（`YYYY-MM-DD HH:MM`）+ 定位（页码/章节/表格/段落）+ **逐字摘录**（用「」包裹）。
- **本地证据必填**：文件名 + 用户提供日期 + 定位 + 逐字摘录（链接栏写"本地文件（无 URL）"）。
- **链接存活复验（v2.5.0 起）**：报告定稿前对全部联网证据 URL 逐条访问复验（WebFetch/浏览器），复验状态写进证据条目「链接」字段——`〔复验：可达 / 重定向 / 不可达(状态码) / 未复验(原因) · YYYY-MM-DD〕`；不可达的不删除证据（保留原抓取摘录与时间），但等级降一档并显著标注。本地模式或预算不足时标〔未复验〕，**不得谎称已验**。复验访问计入联网检索预算，优先复验问题项与 S/A 级证据。
- **无链接不得留空**：写"未取得可访问链接（原因）"或"付费墙未检索"，并相应降低证据等级。
- **绝不编造 URL / 页码 / 摘录**。摘录必须逐字，**不得转述、不得改动单位或正负号**。
- **冲突证据必须全列**并说明采信理由（高等级优先），不得只列有利证据。

完整格式规范（含四种形态模板与自检清单）见 `references/citation-format.md`。

### 9.2 评分推导硬规则（可推导性）

输出分数时**必须**给出：① 统计口径构成（分子/分母 + 对应主张编号）；② 五维公式 → 原始观测 → 得分 → 加权贡献；③ 证据等级分布及对应证据编号（弱来源触发警示）；④ 扣分清单（主张编号 + 证据编号 + 理由）；⑤ 档位（含问题项计数）与附加要求；⑥ 公式来源 + 固定警示 + 自评声明。

**禁止**：只给总分不给推导、无解释扣分、分数与主张清单对不上、档位行不带问题项计数。

模板见 `references/audit-report-template.md`。

## 十、分批审协议（主张数较多时必用）

主张数 > **25 条**时，不得一次性倾倒全部内容（会超轮次、会被静默压缩）：

1. 先输出**主张清单 + 审查计划**（总数、分类计数、高风险项列表、拟分几批）；
2. 按批输出完整主张卡，**高风险主张优先**；
3. 每批结束标注进度（如"第 2/4 批，已审 15/40 条"）；
4. 全部批次完成后才输出总分——**分数必须基于已审全部主张**，不得在未审完时给分。

**联网检索硬预算**：单次核验联网检索总量 **≤ 40 次**；聚焦再搜索每主张 ≤2–3 轮。超出预算时，剩余未检索主张列入「未检索清单」并交回用户，**不得静默少搜**。

## 十二、操守（铁律）

- **不提供投资建议**：不做涨跌预测、买卖建议、宏观预测、立场判断；只做事实核验与证据审计。
- **本地模式实测的孤立事实**不冒充联网核验：联网证据必须标 URL + 抓取时间，显式区分「本地证据」与「联网证据」。
- **不伪装**：不伪装已 OCR、不伪装已联网、不伪装向量检索、不伪装多智能体、不伪装自动改稿、不做无解释评分、不编造演示数据；**不伪装独立复核、不伪装链接复验**——没做就在报告里如实写明。
- **Mock 模式**：无 API Key 时结果带"Mock 模式，非真实模型输出"标识。
- **诚实收口**：绝不把"核验不了"伪装成"通过了"。
