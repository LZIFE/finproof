## B 臂实测的差异化（全部为产出结构，不是检出数）

1. **三分级修复清单**：56 条超容差硬错 / 12 条容差内引用更新 / 2 条弃权——
   对下游是三种不同动作（改数 / 更新引用 / 人工核）；A 臂是一锅端清单。
2. **逐条引擎判定**：每对带相对差%（22.448%、0.415%…）与规则编号（S3/S4/
   R1/R2/S1/Q1–Q3），可复算、可入库；B1/B2 两次判定集合逐条一致。
3. **弃权纪律**：T1/T3（报告无落款，可判性不足）、M1（触发信号不完整）、
   零值（相对差无定义，给方向性说明）——没有硬判。
4. **独有发现**：报告内部自相矛盾（"韩承志 0 股"与"70,759,963 股"并列）；
   证据命中校验 70/70。
5. **规则库的实测作用**：把裸臂靠自由联想抓到的东西（E19 限售、粉饰、无据
   比较）变成**必然执行的留痕动作**；Q2 引擎 `forecast_scan` 强命中
   "板上钉钉"，并对"半导体国产化"句做出 CLEAN+Q3 的细分判定。

## B 臂实测的劣势（同样如实）

**tokens 2.53×（A 151k vs B 383k）**——且成本不在引擎（71 对引擎判定
<1s、0 token），而在**模型侧编排**（逐对 JSON 构造、10 份证据逐份阅读、
表格生成）。这修正了"饱和扫=零成本"的直觉：**引擎消灭的是算术与注意力
成本，消灭不了叙述成本**。

## 工程结论：引擎优先管线（下一步）

把 B 臂的编排成本压回 A 以下的路径已明确：
1. **引擎预对账**：证据对齐（更正前/更正后解析）→ 引擎批量 reconcile →
   只把 violation 清单交给模型——模型从"逐对编排者"变成"例外复核者"；
2. 证据对齐本身可复用 `evaluation/corrections/align_corrections.py`（已含
   五道质量门），模型只在解析失败时介入；
3. 预期：B 臂成本降至 ≈A 或以下，同时保住三分级与逐条判定的产出优势。

## 结论（对"比裸模型牛"的最终回答）

**检出轴：四次实验（v1/v2a/v2b/六轮主线）一致证明，强模型+证据齐全时
"检出更多"不可通过提示词、清单或规则库获得——天花板由模型与证据决定。**
规则库（disclosure-rulebase.md）已固化进 SKILL/LITE，它的价值是把过程纪律
（命中留痕、容差细分、弃权）变成必然执行，而非提升检出。

框架真正"牛"且可测的轴：**①产出可入库**（三分级修复清单+逐条引擎溯源，
两次运行逐条复现）；**②容差细分**（56/12 的动作区分）；**③弃权纪律**；
**④成本结构**——前提是走引擎优先管线（本次实测的 2.53× 是"模型编排"
架构的成本，不是框架的物理下限）。
