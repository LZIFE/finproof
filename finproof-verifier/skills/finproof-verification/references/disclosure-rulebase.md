# A股披露硬规则库（disclosure-rulebase v1 · v2.19.0）

> **定位**：把"审计该懂的世界知识"写死成**规则铰定**的强制检查——每条规则 =
> 规则来源 + 触发信号（文本里出现什么）+ 强制检查动作。与 `error-taxonomy.md`
> 的 89 条泛化检查点不同：那套是"归类与提醒"（实测不提升检出，见
> `evaluation/checkpoints/`），本套是"命中即查的硬规则"——依据是两臂实验的
> 关键分离点：**检出的增量来自领域知识，不来自清单条数**。
>
> **来源**：①《公司法》（董监高转让限制条款，条文号以现行版本为准）、
> ②沪深北交易所《股票上市规则》及定期报告披露格式指引、③《企业会计准则
> 第 28 号——会计政策、会计估计变更和差错更正》、④《上市公司信息披露
> 管理办法》、⑤ **79 对真实更正公告实证**（`evaluation/corrections/`——
> 本库每条规则对应真实错误模式，不是理论清单）。
> ⑥ 提示词技术来源：Factcheck-GPT（Apache-2.0）的去语境化与子任务分解、
> CRITIC 的工具接地批判（判定归程序）。

## 使用方式（规则铰定路由，替代逐组泛扫描）

1. 主张先**去语境化**（改写成自含式："谁、什么指标、什么期间、什么值"）——
   Factcheck-GPT 实践：自含主张才能被独立核验。
2. 对每条自含主张**过本库规则**：命中触发信号 → 执行强制检查动作（引擎子
   命令或证据对照），在审计轨迹留下规则编号与动作输出。
3. 未命中任何规则的数值 → 走通用引擎复算；未命中的定性 → 语义判定 + 弃权纪律。
4. 命中 ≠ 有问题；但**命中 = 必须留痕**，没留痕视为没查。

## R 组：持股与限售（真实错误：国子软件 E19）

- **R1 董监高转让限制**：《公司法》董监高任职期间每年转让不得超过所持股份
  总数的 25%；离职后半年内不得转让。
  触发：董监高/控股股东 + 持股或限售表述 → **强制**：对照"限售/高管锁定股"
  惯例（通常约 75% 登记为高管锁定股），"全部无限售"与规则相悖即 FLAG。
- **R2 限售分类**：控股股东/实控人 IPO 前股份有锁定期；董监高新增"高管
  锁定股"科目。触发："全部为无限售/全部流通" + 主体为董监高 → 查分类。
- **R3 减持规则**：大股东减持需预披露；集中竞价 90 日内减持 ≤ 总股本 1%。
  触发：减持/增持表述 → 对照规则与预披露。

## S 组：报表口径（真实错误：微创光电 E16/E17、汇隆活塞"销售金额"）

- **S1 差错更正 vs 政策变更**：前期差错更正须追溯重述并披露更正公告
  （准则 28 号）；审计调整≠会计政策变更。
  触发："经审计调整/更正" + 正面评价（"更加稳健/打下基础"）→ **强制**：
  查更正公告、量化调整前后差异，正面定性按粉饰嫌疑处理。
- **S2 供应商/客户表口径**：前五名供应商对应"采购金额"，前五名客户对应
  "销售金额"。触发：供应商 + "销售金额"（或反向）→ 口径颠倒 FLAG。
- **S3 引用效力**：公司披露更正公告后，再引用原披露值 = 引用失效数据。
  触发：公司存在更正公告 + 报告引用其定期报告数值 → **强制**：对照更正
  公告的更正后值（证据可得时引擎 match；不可得时按 G1 交回）。
- **S4 调整前后口径**：涉及重述的数字必须标明调整前/后。触发：重述/调整
  + 未标注 → FLAG。

## M 组：货币与资金（真实错误：国义招标 E18 附近"资金充裕"）

- **M1 货币资金受限**：招标代理/建筑等行业的货币资金大头是投标保证金等
  受限/代管资金。触发：货币资金 + "资金储备充裕/支撑扩张" → **强制**：
  查受限资金披露；未披露即"充裕"结论依据不足。
- **M2 资金占用/担保**：大股东资金占用、违规担保是问询函高频。触发：
  资金往来/担保表述 → 查审议程序与披露。

## G 组：比率与增长（真实错误：凯大催化 E01–E06）

- **G1 同比基数**：增长率必须同长度期间、同口径基数；亏损基数取绝对值。
  动作：引擎 `yoy`（分母 |prev|）。
- **G2 恒等式**：资产 = 负债 + 所有者权益；归母净资产 ≠ 所有者权益合计
  （有少数股东权益时）。动作：引擎 `sum_check` + 口径检查。
- **G3 比率复算**：资产负债率/毛利率/周转率可从同表复算。动作：引擎
  `margin`/`match`；复算差异在舍入区间内判通过（容差纪律）。
- **G4 占比加总**：占比列合计=100%；供应商占比分母=采购总额。
  动作：引擎 `sum_check`/`saturation_scan`。

## T 组：期间与引用（真实错误：凯德石英 E09–E11）

- **T1 引用时序**：来源报告覆盖期早于数据期间 = 纯逻辑不可能。动作：
  引擎 `temporal`。
- **T2 季报未经审计**：年报唯一必须经审计；季报/半年报数据引用时不得
  混用"经审计"表述。触发：季报数据 + 审计表述。
- **T3 报告时点 vs 数据时点**：落款 2025 年的报告"预计 2023 年" = 时点
  倒置；旧数据做"现在时"判断须披露滞后。触发：报告日期 + 预测期间。

## Q 组：研报断言（真实错误：E07/E08/E12，两臂实验中裸臂靠自由联想抓到——
写成规则让它必中）

- **Q1 比较断言**："显著高于同业/领先水平/第一/核心供应商" 必须有同业
  样本、数值、口径、来源，缺一即无据断言。
- **Q2 预测事实化**：确定性措辞（板上钉钉/必将/已无悬念）+ 依据未披露 →
  动作：引擎 `forecast_scan`，FLAG 进问题项。
- **Q3 编造因果**："主要系/受益于/拉动" 需原文或数据佐证，单因素归因且
  无量化占比 → 无据归因。
- **Q4 历史极值**："创历史新高/历史低位" 需历史序列，未提供即无法支撑。
