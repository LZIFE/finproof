# FinProof MVP 范围说明书

> 版本：v1.0（2026-07-31）
> 上游依据：`docs/finproof_product_spec.md`、`docs/finproof_audit.md`
> 定位：将产品说明书收缩为一个**能在黑客松现场真实运行**的最小闭环；本文件是开发范围与验收的唯一约束，后续一切阶段划分以本文件为准。

---

## 一、MVP 用户场景

### 1.1 一句话场景

> 分析师上传一份待审核的上市公司研究报告 PDF 和对应的原始财务证据 PDF（年报/季报/公告），FinProof 自动把报告拆成一条条可核验的金融主张，逐条找到证据、重算数字、给出"支持 / 反驳 / 部分支持 / 证据不足 / 无法判断"的结论，并在三栏界面展示"报告原句 → 原始证据 → 计算过程"，最后导出一份可追溯的审计报告。

### 1.2 一次典型会话（演示剧本）

| 步骤 | 用户操作 | 系统响应 | 对应页面 |
| ---- | -------- | -------- | -------- |
| 1 | 打开首页，上传研究报告 PDF + 1 份证据 PDF | 校验文件类型/大小，显示已上传文件清单 | 上传页 |
| 2 | 点击"开始核验" | 运行解析 → 提取 → 匹配 → 计算 → 判定流水线，返回总览 | 总览页 |
| 3 | 查看总览 | FinProof Score、主张总数、各类核验结果计数、风险等级 | 总览页 |
| 4 | 点击某条主张 | 三栏展示：报告原句（含页码）/ 原始证据（含证据文件与页码）/ 计算过程（公式、输入、结果、与报告原值差异） | 主张详情页 |
| 5 | 点击"导出审核结果" | 下载 JSON / HTML 审计报告 | 导出（总览页按钮） |

### 1.3 演示中的"高光时刻"（必须可现场复现）

1. **致命错误展示**：报告把"上半年累计收入"写成"第二季度单季收入"，系统在计算栏给出 `Q2 = H1 − Q1` 的推导过程并判定"反驳"。
2. **确定性重算**：报告的同比增长率与财报原始数字重算结果不一致，系统判定"反驳"并显示计算步骤。
3. **审慎拒绝**：一条证据不足的因果结论被判定为"无法判断"，而不是强行二选一。
4. **证据可追溯**：每条主张的证据都带文件与页码，可在证据 PDF 原页核对。

## 二、输入与输出

### 2.1 输入

| 输入 | 格式 | 数量 | 约束 |
| ---- | ---- | ---- | ---- |
| 待审核研究报告 | PDF | 1 份 | 必须为**文本型 PDF**（可提取文字）；不支持扫描件/OCR |
| 原始证据文件 | PDF | ≥1 份（推荐 1 份年报） | 上市公司定期报告/公告；文本型 PDF |
| （评测模式可选）金标准 | JSON | 1 份 | 仅评测脚本使用，不参与产品流程 |

### 2.2 输出

| 输出 | 形式 | 说明 |
| ---- | ---- | ---- |
| 核验总览 | JSON（API）+ 页面 | FinProof Score（0–100）、主张总数、五类结果计数、风险等级 |
| 逐条主张核验 | JSON（API）+ 三栏页面 | 报告原句与页码 / 证据文本与页码 / 计算过程与差异 |
| 审计报告导出 | JSON / HTML 文件 | 含全部主张、判定理由、证据位置、计算过程、得分明细 |
| 评测指标（评测模式） | Markdown / 控制台 | 错误召回率、误报率、证据匹配率、拒答准确率 |

### 2.3 混合核验架构原则

FinProof 不是纯规则系统，也不是完全依赖大模型的系统，而是**混合核验架构**：

- **确定性程序负责**：数字格式标准化、单位和币种处理、同比增长率/环比增长率计算、累计数据转单季度数据、财务比率计算、数值差异比较、计算过程记录。
- **大模型负责**：金融主张拆解、指标和期间的语义识别（规则词典未命中项的兜底）、非结构化证据理解、主张与证据之间的支持关系判断、因果关系过度推断检测、预测事实化检测、审慎修订建议。
- **无 API Key 时的运行约束**：系统必须能通过明确标识的 **Mock 模式**（`FINPROOF_LLM_MODE=mock`）或人工标注数据回放继续运行；Mock 结果必须带"Mock 模式，非真实模型输出"标识，**不得伪装成真实模型结果**；语义判断输出在 Mock 模式下来自金标准/人工标注并如实标注来源。

## 三、功能边界（MVP 必须包含）

以下 15 项为 MVP 硬性范围，逐项对应任务书要求：

| # | 功能 | 任务书要求 | 实现方式 |
| - | ---- | ---------- | -------- |
| 1 | PDF 研究报告上传 | 必须 | FastAPI 上传接口 + 本地文件存储 + 元数据入库 |
| 2 | PDF 原始证据文件上传 | 必须 | 同上（支持一次多文件，至少 1 份证据） |
| 3 | 保留页码的文本解析 | 必须 | PyMuPDF 按页提取，页码与页序入库 |
| 4 | 金融主张提取 | 必须 | 规则初筛数字型主张 + 大模型拆解主张与指标/期间语义识别；无 API Key 时走明确标识的 Mock 模式（见 2.3） |
| 5 | 数字、指标、期间、单位、币种结构化 | 必须 | 正则 + 指标词典 + 期间归一化（Q1–Q4/上半年/全年/同比） + 单位表（元/万元/亿元/%/亿股等） + 币种表（人民币/港币/美元） |
| 6 | 主张与原始证据匹配 | 必须 | 指标关键词 + 数值匹配 + 页码定位，输出证据段落与页码 |
| 7 | 同比增长率计算 | 必须（至少） | 确定性计算引擎：`(本期 − 上年同期) / 上年同期` |
| 8 | 累计数据转换为单季度数据 | 必须（至少） | `Q2 = H1 − Q1`、`Q4 = 全年 − 前三季度` 等减法规则 |
| 9 | 五类核验结果 | 必须 | 支持 / 反驳 / 部分支持 / 证据不足 / 无法判断；数字类判定由确定性计算驱动，语义类（支持关系/因果/预测）由大模型判断，无 Key 走 Mock；每条附理由 |
| 10 | 三栏展示 | 必须 | 报告原句 / 原始证据 / 计算过程三栏页面 |
| 11 | 含预埋错误的演示数据 | 必须 | 1 家真实公司 + 真实年报 PDF + 预埋 8~12 处错误的研报 + 金标准 JSON |
| 12 | 基础评测指标 | 必须 | 错误召回率、误报率、证据匹配率、拒答准确率（对金标准计算） |
| 13 | 审核结果导出 | 必须 | JSON + HTML 导出 |
| 14 | FinProof Score 与总览统计 | 建议（说明书 P0） | 五维加权分 + 分类计数，作为总览页核心 |
| 15 | 工程骨架与可运行闭环 | 隐含 | git 仓库、依赖清单、启动文档、`/api/health` |

### 3.1 主张覆盖的核验类型（Phase 3–6 的目标）

| 类型 | 示例 | MVP 判定能力 |
| ---- | ---- | ------------ |
| A 原始数字主张 | "2025 年营业收入 120 亿元" | 与证据数字比对 → 支持/反驳 |
| B 计算型主张 | "收入同比增长 20%" | 重算同比 → 比对 |
| C 口径主张 | "第二季度净利润 5 亿元" | 累计转单季 → 比对（**MVP 核心卖点**） |
| 证据不足/无法判断 | 无法在证据文件定位到数据 | 输出"证据不足/无法判断" |

> 说明：说明书中的 D（业务事实）、E（因果）、F（比较）、G（预测）类主张**不是 MVP 必选**，识别到可归入"无法判断"并注明类型，不展开核验（见第四节非目标）。

### 3.2 数据模型（MVP 固定 7 张表，详见执行计划 Phase 2–6）

`documents` / `pages` / `claims` / `evidence` / `calculations` / `verifications` / `audit_runs`，与说明书第十节结构对齐（字段裁剪到 MVP 必需）。金标准单独以 JSON 存放于 `data/demo/gold_errors.json`，不入库。

## 四、非目标（MVP 不包含）

### 4.1 任务书明确的非目标

| # | 非目标 | 说明（为什么不进 MVP） |
| - | ------ | ---------------------- |
| 1 | 股票涨跌预测 | 超出核验定位；说明书自身也明确第一阶段不做 |
| 2 | 自动投资建议 | 定位是"质量控制层"而非决策引擎 |
| 3 | 全网新闻真实性判断 | 无数据源、无爬虫，范围爆炸 |
| 4 | 复杂知识图谱平台 | 说明书证据链图谱列为高级展示；MVP 用结构化的证据引用关系替代 |
| 5 | 多租户企业权限 | 无用户体系，单机演示 |
| 6 | 完整私有化部署 | Docker/离线模型等为 P2 |
| 7 | 大规模爬虫 | 与"模式一（上传证据包）"冲突，且不稳定 |
| 8 | 全行业规则市场 | P2 商业化形态 |
| 9 | 自动发布研究报告 | 系统只审核、建议，不发布 |
| 10 | 没有真实实现的占位功能 | 见 4.2 伪功能禁止清单 |

### 4.2 伪功能禁止清单（宁可少做，不可假装）

| 禁止项 | 禁止原因 | 正确做法 |
| ------ | -------- | -------- |
| 假装支持扫描件 / OCR | 未实现 OCR，扫描 PDF 会解析为空 | 上传时校验"能提取到文本"，否则明确报错 |
| 假装多智能体编排 | 无真实 Agent 框架，只是流水线函数 | 如实命名为"核验流水线（pipeline）" |
| 假装向量数据库 / 语义检索 | 无 Embedding 服务 | 只用关键词 + 指标精确匹配，如实说明 |
| 假装全网搜索 / 自动找财报 | 无爬虫与外部数据源 | 只核验用户上传的证据文件 |
| 假装自动生成修订版报告 | 未实现 LLM 修订生成 | 只给"修改建议"文本 |
| 假装大模型核验 | 无 API key 假设 | 数字与计算全确定性；语义类任务在无 Key 时走明确标识的 Mock 模式（输出带"Mock"标识），不得伪装成真实模型结果 |
| 假评分（无解释） | 评分无依据即不可信 | 每个扣分项必须有对应主张与理由 |
| 编造演示数据 | 评委一问即穿 | 数字必须来自真实披露，错误必须逐条记录金标准 |

### 4.3 明确"不做"的纵深项（说明书 P1/P2，MVP 一律推迟）

- 语义检索 / Reranker、跨文件矛盾检测、自动修复全文、证据链图谱页、修改 diff 对照页、审核日志、中英文双语、API 商业接口、Excel/PDF 导出（MVP 只导出 JSON/HTML）、观点/预测标签（识别后并入"无法判断"并注明）。

## 五、验收标准

### 5.1 功能验收（每条均可现场演示）

| # | 验收项 | 判定标准 |
| - | ------ | -------- |
| F1 | 上传 | 上传 1 份研报 + 1 份年报 PDF，接口返回成功且文件落盘 |
| F2 | 解析 | 数据库中存在 documents 与 pages 记录，页码连续且每页文本非空；对文本型 PDF 不出现空页 |
| F3 | 主张提取 | 演示研报中至少提取 20 条主张，含数字、单位、期间字段 |
| F4 | 结构化 | 抽查 10 条主张：数字/指标/期间/单位/币种字段与原文一致 |
| F5 | 证据匹配 | 每条主张至少给出 1 条带页码的证据（目标覆盖率 ≥85%，如实报告） |
| F6 | 同比计算 | 报告中的同比增长率与财报数据重算结果一致或可解释差异（容差内） |
| F7 | 累计转单季 | 预埋的"上半年当单季"错误被检出并判定为反驳，计算栏显示 `Q2 = H1 − Q1` |
| F8 | 五类判定 | 演示结果中出现至少 4 类不同结果（如支持/反驳/证据不足/无法判断） |
| F9 | 三栏展示 | 详情页三栏齐全：报告原句（页码）/ 证据（文件+页码）/ 计算过程（公式+输入+结果） |
| F10 | 导出 | 点击导出分别得到可打开的 JSON 与 HTML 审计报告，内容与页面一致 |

### 5.2 数据验收（演示数据与金标准）

| # | 验收项 | 判定标准 |
| - | ------ | -------- |
| D1 | 真实性 | 演示财报文件为真实上市公司披露 PDF（来源记录在 `data/demo/README.md`） |
| D2 | 预埋错误 | 研报中预埋 8~12 处错误，覆盖：数字错误、计算错误（同比算错）、口径错误（累计当单季）、证据不足、时间过期、单位/币种混淆 |
| D3 | 金标准完整 | `gold_errors.json` ≥20 条主张，且**同时包含**：预埋错误条目（测错误召回率）、正确条目（测误报率）、证据不足条目（测拒答准确率）；每条含 claim_id / original_text / verdict / error_type / planted_value / correct_value / source_page / note |

### 5.3 质量验收（基础评测指标，现场如实展示）

| 指标 | 定义 | MVP 目标值（开发目标，不预先宣称达标） |
| ---- | ---- | --------------------------------------- |
| 错误召回率 | 预埋错误中被系统发现的占比 | ≥90%（对预埋错误） |
| 误报率 | 正确主张中被系统错误标记的占比 | <10% |
| 证据匹配率 | 匹配到带页码证据的主张占比 | ≥85% |
| 拒答准确率 | 证据不足主张中输出"证据不足/无法判断"的占比 | ≥80% |

> 指标由 `tests/evaluation/eval.py` 对 `data/demo/gold_errors.json` 计算，结果写入 `data/demo/eval_report.md`；演示只展示真实数值。

### 5.4 运行验收

| # | 验收项 | 判定标准 |
| - | ------ | -------- |
| R1 | 一键启动 | 按 README 指引，后端 `uvicorn` + 前端 `pnpm dev` 两条命令即可启动 |
| R2 | 离线可运行 | 不配置任何 API key 也能完成上传→核验→导出全流程 |
| R3 | 性能 | 单份短报告（≤30 页）从上传到出结果 ≤3 分钟 |
| R4 | 无残留 | 演示前后数据库/文件目录状态一致（无脏数据） |
