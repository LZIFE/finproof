# 错误分类体系（Error Taxonomy）

FinProof 的检测能力划分为九种错误。核验时按此体系归类每条被反驳/部分支持的主张。

| # | 错误类型 | 定义 | 高频触发点 |
|---|---|---|---|
| 1 | **数字错误** | 报告数字与原始文件不一致 | 抄写/录入偏差 |
| 2 | **计算错误** | 原始数字正确，但同比/环比/利润率/占比计算错误 | 增长率公式用错基数 |
| 3 | **时间错误** | 使用错误年份/季度或过期信息 | 把去年同期当今年 |
| 4 | **口径错误** | 口径混用导致结论失真 | 单季↔累计、营收↔主营收入、归母↔净利润、调整前↔调整后、合并↔母公司、人民币↔港币/美元 |
| 5 | **引用错配** | 引用文件真实存在，但内容无法支持对应结论 | 断章取义、张冠李戴 |
| 6 | **证据不足** | 报告给确定性判断，但材料只能部分支持或完全无法支持 | 缺原始披露佐证 |
| 7 | **跨文件矛盾** | 同一公司不同文件/页面/版本数据互相冲突 | 多版本报告口径不一致 |
| 8 | **因果关系过度推断** | 两现象同时发生，报告却直接认定因果 | "毛利率升+原料降价"→"由原料降价推动" |
| 9 | **预测事实化** | 把预测/管理层目标/市场预期写成既成事实 | "预计破百亿"→"已破百亿" |

## 使用提示

- **口径错误（#4）是最高频雷区**：核验数字类主张时，必须显式核对单季/累计、合并/母公司、币种、调整前后。
- **证据不足（#6）与无法判断要区分**：材料"部分支持"→ 证据不足；材料"完全无法获取/无法判定"→ 无法判断。
- 每条被标记的错误都应回链到具体证据与复算过程（见 `verdict-and-evidence.md` 与 `audit-report-template.md`）。

# 检查点清单（v2.16.0 · 89 条）

上面的九类是**归类用**（判完之后把问题贴标签）。下面这 89 条是**发现用**——拆解主张时逐条过，命中触发信号就执行对应检查。

为什么需要它：拆解靠"读一遍、想到什么查什么"，想到什么取决于模型当时注意到什么。把检查点写成固定清单，等于把"敏感度"从临场发挥变成可以逐条执行的流程。清单不提高模型的判断力，它提高的是**同一份报告被注意到的东西的下限**。

用法：**扫描触发信号 → 执行检查 → 记结果**。没命中的跳过，命中的必须留下检查痕迹（查了、结论是什么），不得默认放行。

## A · 数字与计算（10 条）

| # | 触发信号（文本里出现就查） | 要查什么 | 典型表现 |
|---|---|---|---|
| A1 | 任意同比/环比百分数 | 用两期原始值重算，不采信报告给的增速 | 基数抄错、分母用了本期 |
| A2 | "提升/下降 X 个百分点" | 是 pp 还是 %？两期比率相减是否等于 X | pp 与 % 混用 |
| A3 | 任何比率（毛利率/净利率/费用率/占比） | 分子分母是否为同一口径同一期间 | 分子含税分母不含、分母用总营收分子用分部 |
| A4 | 多期数据并列 | 逐期复算，注意基期是否被追溯调整 | 上年数已重述，报告仍用原披露值 |
| A5 | CAGR / 复合增速 / 年均增速 | 起止点是"首年末"还是"年初"？年数怎么取 | 3 年数据按 2 年算 |
| A6 | EPS / 每股指标 | 股本是否期间变动（送转、增发、回购） | 用期末股本算全年 EPS |
| A7 | "合计/总计/累计" | 分项之和是否等于合计（跑 `sum_check`） | 少加一项、重复计一项 |
| A8 | 差额类表述（"增加 X 亿"） | 是绝对额差还是增长率？两期相减是否对得上 | 把增幅额写成增幅率 |
| A9 | 任何"约/近/超过/不足" | 模糊词的边界是否被证据支持 | "超过 15%"实为 12.11% |
| A10 | 同一指标在文中出现两次以上 | 两个数是否一致 | 正文与表格、摘要与正文打架 |

## B · 口径位移（12 条 · 最高频）

| # | 触发信号 | 要查什么 | 典型表现 |
|---|---|---|---|
| B1 | "营业收入"与"营业总收入"同时出现 | 两者是否被当成同一个数 | 用总营收替代营收，或反之 |
| B2 | "归母净利润"与"净利润" | 是否混用（差额为少数股东损益） | 把净利润当归母 |
| B3 | "扣非"与"归母" | 是否混用（差额为非经常性损益） | 用扣非增速描述归母 |
| B4 | "单季"与"累计/上半年/全年" | 是否用累计值充单季 | 上半年数直接写成 Q2 |
| B5 | "合并"与"母公司" | 报表主体是否一致 | 母公司报表数当合并数 |
| B6 | "调整前"与"调整后" | 会计政策/追溯重述前后是否混用 | 用调整前毛利率对比调整后 |
| B7 | "主营业务收入"与"营业收入" | 是否混用（差额为其他业务） | 主营增速描述总营收 |
| B8 | 分部/业务线收入 | 分母是总营收还是分部合计？含不含内部抵消 | 分部占比加起来超 100% |
| B9 | "毛利率"跨口径对比 | 两期是否同一计算口径（是否含运费、是否含税） | 新收入准则前后直接比 |
| B10 | "市占率/份额" | 分母是什么（销售额/销量/出货量）？口径是否与对比方一致 | 自家出货量比行业销售额 |
| B11 | "经营性现金流" | 是经营现金流净额还是含投资？（是否含票据） | 净额与总额混用 |
| B12 | 港股/美股标的的"股东应占溢利" | 与 A 股"归母净利润"是否等同使用；财年是否等于自然年 | 3 月财年当 12 月财年 |

## C · 期间与时点（11 条）

| # | 触发信号 | 要查什么 | 典型表现 |
|---|---|---|---|
| C1 | "据《XXXX 年年度报告》" | 该报告的覆盖期间是否包含所引数据的期间（跑 `temporal`） | 用 2025 年报支撑 2026H1 数据 |
| C2 | 报告日期 / 发布日期 | 与数据可得日期是否矛盾（数据早于来源=不可能，晚于来源=可能过期） | 2025 年 3 月发布 2025 年报 |
| C3 | "最新/当前/截至今日" | 核验日与报告撰写日是否一致；是否有快照时点 | 用核验日行情判历史主张 |
| C4 | 季度/半年度数据 | 期间是否闭合（H1 = Q1+Q2） | 用 Q1 数据代表 H1 |
| C5 | "全年/年度"与季度并列 | 是否存在缺失季度被跳过 | 只有 Q1 和 H1，却推 Q4 |
| C6 | 财年非自然年的公司 | 财年跨度是否与自然年混淆 | 财年 Q1 ≠ 自然年 Q1 |
| C7 | 同比对比的两个期间 | 是否同长度（H1 vs H1，不是 H1 vs 全年） | 半年比全年 |
| C8 | "预计/指引"的时间锚点 | 指的是哪个财年 | 2026 指引当 2025 实际 |
| C9 | 上市/并购/剥离的时点 | 期间是否可比（有无并表天数差异） | 并购当年直接同比 |
| C10 | **期间用自然语言表述**（"three months ended March 31, 2026"、"fiscal year ended January 28"、"截至 3 月 31 日止三个月"） | 不要只认 `Q1–Q4` / `FY` 这类标记，先解析成**期间类型 + 起止日**再比对 | 只按 `Q` 做匹配的检查器会被 "three months ended" 绕过（AnamnesisBench OOD-0021） |
| C11 | **两个期间都是年度** | 结束日是否相同（财年可结束于 1 月、6 月等非 12 月） | "FY ended Jan 28" vs "FY ended Dec 31"，类型相同但窗口不同（OOD-0023） |

| # | 触发信号 | 要查什么 | 典型表现 |
|---|---|---|---|
| D1 | 任何"据/来源/引用/第 X 页" | 跑 `cite_check`：链接可达、摘录逐字命中 | 链接 404、摘录改写 |
| D2 | 引用页码 | 该页是否真有该内容 | 页码漂移（PDF 物理页 vs 印刷页） |
| D3 | 引用文件名 | 文件是否真实存在、版本是否最新 | 引用旧版年报 |
| D4 | 引用一句话支撑一个结论 | 摘录是否支持该结论（而不只是提到关键词） | 断章取义 |
| D5 | 转述式引用（无引号） | 是否改变了原意、单位、正负号 | "下降"转述成"改善" |
| D6 | 引用行业协会/第三方数据 | 该机构是否真实存在、数据是否可回溯 | 编造机构名 |
| D7 | 引用"公司公告" | 公告日期与编号是否可查 | 公告不存在 |
| D8 | 同一处引用支撑多条主张 | 是否每条都真的被支持 | 一条摘录套用全段 |

## E · 比较与对标（7 条）

| # | 触发信号 | 要查什么 | 典型表现 |
|---|---|---|---|
| E1 | "高于/低于行业平均 X" | 行业数据来源、口径、样本是否与本公司可比 | 无来源的行业均值 |
| E2 | "领先/第一/龙头" | 排名依据是什么榜单、什么指标、什么年份 | 用某细分领域第一冒充全行业 |
| E3 | 同业对比 | 对比对象的指标定义是否相同（如毛利率是否同含运费） | 口径不同直接比 |

## K · 格式与类型变体（4 条 · 判之前先规范化）

这几条不产出新错误类型，它们决定前 79 条的命中率能保住多少。AnamnesisBench 的分布外测试显示：规则逻辑全对、但过不了表述变体，捕获率会从 1.00 掉到 0.64。

| # | 触发信号 | 要查什么 | 典型表现 |
|---|---|---|---|
| K1 | 枚举值大小写/前后空格不一 | 比较前 `strip().lower()`，不要字面比 | `User_Response` / `" user_response "` 被当成不同来源而误判 |
| K2 | 字段名与预期不符或为 null | 先看同义键是否有值（如 `current_period` vs `current_year_period`），再判缺失 | 键名漂移被当作"字段缺失"直接弃权 |
| K3 | 全角数字/符号（４２.０％） | 归一化全角→半角后再解析 | 全角数字导致数值解析失败 |
| K4 | 数值字段是字符串或带货币符号（`"8.4"`、`"$8,400 million"`） | 统一走数值解析器，容忍千分位、符号、中文单位（亿/万） | 直接相减抛 TypeError，或把 8.4 亿当 8400 百万 |

## L · 可判性与弃权（6 条 · v2.16.0）

这几条不找"数字错在哪"，而是防止**证据不够却硬判**。判定前先过 `claim_gate`；两次抽取不一致先过 `dual_extract`。

| # | 触发信号 | 要查什么 | 典型表现 |
|---|---|---|---|
| L1 | 主张有数值，但找不到对应期间/指标的原文 | 是否满足 PASS 的最低证据条件（`claim_gate`） | 无证据仍判"支持" |
| L2 | 单位同类但不可比（亿元 vs 亿美元、吨 vs 千瓦时、% vs 百分点） | 币种/量纲/比率口径是否一致 | 数值相同就判通过 |
| L3 | 同一期间有两条以上证据且数值不一致 | 是否应弃权而不是挑一条 | 挑对自己结论有利的一条 |
| L4 | 两次独立抽取的指标/数值/期间/口径不一致 | 是否 `EXTRACTION_CONFLICT` → 弃权/第三来源 | 取平均或投票统一 |
| L5 | 期间缺失或无法归一化（"去年"/"当时"/"某个季度"） | 能否建立本期/上年同期对应 | 用自然语言期间硬算同比 |
| L6 | 定义域外计算（负净资产 ROE、负基数 CAGR、零分母） | 是否应拒绝并说明，而不是给数 | ROE 50%、CAGR 21.4% |

## 两阶段执行（v2.16.0：89 条不能一次过完）

**问题**：89 条逐条过 ≈ 15–25 轮工具调用；加上 51 条主张逐条复算（51 轮）、引用核验（10 轮）、复核输出（10 轮），一次长报告审计要 94–104 轮。**清单越厚，越跑不完——条目会被读一遍然后被截断。**

**做法**：分两阶段。第一阶段固定做完，第二阶段按触发信号展开。

### 第一阶段 · 必查核心（12 项，每次审计都做）

这 12 项覆盖引擎的 7 个命令 + 最高频口径错，是"不做就等于没审"的部分。

| # | 动作 | 引擎 | 判据 |
|---|---|---|---|
| 1 | 所有同比/环比百分数重算 | `yoy` / `qoq` | 0.5pp |
| 2 | 所有"提升/下降 X 个百分点" | 手算两期比率 | pp ≠ % |
| 3 | 所有合计行/分项之和对账 | `sum_check` | 相对 0.1% |
| 4 | 营业收入 vs 营业总收入 | 口径双栏 | 是否被当同一个数 |
| 5 | 归母净利润 vs 净利润 vs 扣非 | 口径双栏 | 三者是否混用 |
| 6 | 单季 vs 累计 | `quarter` | 是否用累计充单季 |
| 7 | 每条引用型主张的来源期间 | `temporal` | 覆盖期间早于数据期间 → 直接反驳 |

### 第二阶段 · 按需展开（其余 77 条）

只在第一部分命中的触发信号附近展开同类条目。例：

### 批量复算纪律（v2.12.0，直接决定轮次）

**不要把 51 条主张拆成 51 次工具调用。** 把同一类计算合并进一次 Bash：

```bash
P=…; { python3 "$P" yoy --current 439.45 --previous 385.37; \
       python3 "$P" yoy --current 2523.31 --previous 2180.5; \
       python3 "$P" quarter --h1 2523.31 --q1 1278.39; } | tee /tmp/recalc.log
```

实测可把 51 条主张的复算从 ~51 轮压到 6–10 轮。**审计轨迹仍逐条可溯源**（引擎输出里每条都有命令回显），不因批量而损失可核性。

## 清单使用纪律

1. **命中必留痕**：触发信号出现就必须检查，查完写结论（哪怕"已查，无异常"）。没留痕视为没查。
2. **清单不是判据**：命中不等于有问题。A1 触发只是"要重算"，重算通过就是通过——**不得为了凑数把正常项判成问题**（误报的代价和漏报一样高，五轮实测基线误伤 2–3 处）。
3. **优先级**：B 组（口径）与 D 组（引用）命中率最高，预算有限时先过这两组；A 组交给引擎（`match/yoy/margin/sum_check`），不占模型注意力；**K 组在动手判定前先过一遍**，否则前面的规则会被表述变体绕过。
4. **与规模门联动**：抽样审时，用清单密度决定抽哪一段——某段命中 B/D 组信号多，优先抽该段。
5. **新增检查点必须来自真实错例**：每条都要能指到一个实际发生过的错误类型，不写"理论上可能"的条目。
