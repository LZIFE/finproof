# 鉴融—通用 AI 报告审计专家（FinProof Verifier）

**English**: Jianrong (FinProof) is a general-purpose **audit agent for AI-generated reports**. It decomposes a report into checkable claims, recomputes every number with a deterministic engine at published tolerances, checks citations (including temporal-impossibility detection — a source whose coverage period predates the data period is rejected by logic alone), emits six-class verdicts with full evidence chains, and outputs a dual-score audit: **FinProof Score** (the audited report's evidence-chain quality) alongside an **Audit Quality Score (AQS)** (the audit process itself — coverage, recompute rate, citability, review completion, link re-checks). Every score is recomputable from published formulas; honesty rules (never fabricate URLs, never fake reviews, gaps returned as actionable checklists) are enforced throughout. See [evaluation/](../evaluation/) for six-round head-to-head benchmarks against bare-prompt baselines and the Fin-Fact real-world corpus.

> **任何 AI 生成的报告**（行业研究、市场分析、竞品分析、商业模式、公司深度、尽调、商业计划书、投资备忘录、财务分析，以及政策解读、数据白皮书、技术评估、合规纪要）的 **AI 写稿后审计层**——AI 把写稿压到几分钟，也批量生产了事实错误、口径混淆、数字矛盾与编造引文；鉴融逐条找出这些错误，给出**可溯源、可复核、分数可复算**的审计结论。金融/上市公司研报是验证最深的场景。

`finproof-verifier` 是一个基于本地 **FinProof** 全量资料构建的 Agent 型智能体。它的工作不是"再写一篇报告"，而是**当审稿人**：把报告拆成可独立核验的结构化主张，用确定性计算引擎对照原始材料亲自复算数值，按八步决策链给出六类判定，并指出九类常见错误，最终输出一份可追溯的审计报告。金融/上市公司研报是验证最深的场景，方法论与判定链对商业分析类报告通用。

> **v2.0.0 起两项结构变化**：
> 1. **方法论迁入 Skill**（`skills/finproof-verification/`），并在 `plugin.json` 的 `skills` 字段声明——此前放在插件根目录 `references/`，既未声明也不在规范支持的资源类型内，存在"方法论未被装载"的风险。
> 2. **评分完全透明**：FinProof Score 的五维公式、惩罚系数、取整规则、证据等级分值、CRITICAL 门槛、两份完整算例全部公开（见 `skills/finproof-verification/references/scoring-spec.md`），**任何分数都可被用户自己复算**。

## 一、它解决什么问题

AI 生成研报已经很普遍，但金融数字正是大模型最容易"幻觉"的地方：把累计当单季、把母公司当合并、把去年当今年、把预测当事实、把"同比增长 20%"算成"增长 20 个百分点"……这些错误肉眼难查，发布出去就是风险。

本智能体的定位就是**在研报发布前做一道事实核验闸门**：

- 对研报里的每一个数字，**不止看它"像不像真的"，而是真正重算一遍**；
- 对每一条结论，**给出证据 → 计算 → 判定依据的完整链路**，可逐步核对；
- 对查不到的外部数据，**如实说"证据不足"，绝不假装已核实**。

## 二、适用对象与场景

| 场景 | 说明 |
|---|---|
| AI 研报发布前自检 | 把模型生成的研报贴进来，先过一遍事实核验再对外发出 |
| 人工研报 / 外包报告复核 | 分析师、研究员用来快速找出报告里的口径与计算雷区 |
| 投资/研究团队质控 | 作为报告入库前的标准化质量体检 |
| 教学 / 演示 | 展示"一份研报可能被哪些数字错误坑到" |

**不做的事**：不提供投资建议（不预测涨跌、不给买卖建议、不做宏观预测），只做事实核验与证据审计。

## 三、核心定位与设计哲学

1. **数字归程序，语义归模型，判定有溯源。** 所有数字比对（单位/币种换算、同比环比、累计转单季、比率比较）走**确定性复算**，可复现、零幻觉；只有主张拆解、语义识别、证据支持关系、因果/预测检测才交给大模型。数值判定必标判定来源（引擎/心算），审计轨迹保留引擎命令与输出——"确定性"要有运行证据，不能只靠声明。
2. **自核算，无前端。** 智能体直接在对话里完成"提取 → 复算 → 判定 → 输出"，自身携带 FinProof 的确定性计算引擎（`skills/finproof-verification/bin/finproof_calc.py`，纯标准库 Python，`decimal` 精确运算），不再依赖任何网页界面或独立后端服务。
3. **不假装。** 扫描件 OCR 走**真实识别路径**（渲染 + 本机 tesseract / 多模态视觉）并标注识别置信；不伪装多智能体编排、不伪装向量库/语义检索、不伪装自动生成修订版、不伪装大模型核验；**不做无解释评分、不编造演示数据**。无能力时如实说明（如无 shell 须标〔心算估算，未经引擎复算〕）。
4. **评分透明。** 分数不是"感觉分"——五维公式、惩罚系数、证据等级分值、档位与算例全部公开，**用户可自行复算**；输出必须附五维明细与扣分清单（见第六节）。
5. **诚实收口。** 核验不了的项按 G1–G4 归类、按影响度排序交回用户，并声明「**未闭环 ≠ 通过**」。不追求虚假的 100% 覆盖。

## 四、工作原理：核验流水线（8 步）

```
⓪ 加载 Skill（finproof-verification）——未加载即视为未按方法论执行
        ▼
① 受理与范围判定（Scope Gate）
        │  用户给：报告文本 + 证据来源；确认本地模式 / 联网模式；确认运行档位（完整档 / 快速档）
        │  记录模型/模式/时间；确认宿主是否提供子代理/第二模型
        ▼
② 主张提取与分类
        │  拆成 A–G 七类结构化主张（编号按原文顺序），标风险等级；>25 条先出审查计划再分批
        ▼
③ 证据比对与复算
        │  对照原始材料，按容差表亲自复算（数值 0.1% / 增长率 0.5pp）
        │  判定标〔引擎复算〕/〔心算估算〕，审计轨迹留引擎命令与输出；统计覆盖 N_e/N_v（固定口径）
        ▼
④ 八步判定链 + 对抗性防御叠加
        │  证据→实体→指标→期间→口径→数值→语义→映射；五类对抗性检查同步过
        │  引用三对齐含时序不可能检查；G 类逐条标注依据已披露/未披露，确定性预测进问题项
        ▼
⑤ 需求判定门 + 联网补证 + 聚焦再搜索（仅联网模式）
        │  本地够 → 跳过联网；缺口确需外部数据 → 联网补证（≤40 次）→ 聚焦再搜索 ≤2–3 轮
        ▼
⑥ 独立复核（v2.5.0）
        │  问题项逐条 + 支持项抽样的盲复核；异源第二模型经子代理优先（如 GLM-5.3 → GLM-5.3-Flash）
        │  同源盲复核兜底；自检复核〔机械层〕为最低保障；分歧逐条披露（independent-review.md）
        ▼
⑦ 审计输出
           健康度（含五维明细、弱来源警示与扣分清单）→ 主张卡 → 自核清单（排序）
           → 对抗性抽查 → 独立复核 → 审计轨迹（含引擎命令）；定稿前证据链接逐条存活复验
```

## 五、能力详解

### 5.1 主张拆解（Claim Decomposition，A–G 七类）

把整篇报告直接丢给模型判断是危险的。智能体先**拆解**成相互独立、可核验的结构化主张：

| 类型 | 说明 | 核验重点 | 示例 |
|---|---|---|---|
| **A 原始数字主张** | 直接陈述的财务数值 | 数字/单位/币种/时间/合并或母公司口径 | 2025 年营收 120 亿元 |
| **B 计算型主张** | 含同比/环比/比率等推导 | 需取两期间数据重算 | 2025 年收入同比增长 20% |
| **C 财务口径主张** | 涉及单季/累计等口径 | 原文件披露的是单季还是累计 | 第二季度净利润 5 亿元 |
| **D 业务事实主张** | 定性业务结论 | 海外占比/增长率/管理层表述/分部数据 | 海外业务成第二增长曲线 |
| **E 因果关系主张** | 归因型结论 | 原始资料是否支持所引原因 | 毛利率上升由原料降价推动 |
| **F 比较型主张** | 同业/对标比较 | 同行选择/指标/期间/来源/"显著高于"标准 | 盈利能力显著高于同行 |
| **G 预测和观点** | 前瞻/主观判断 | 标记预测/假设/主观，核查是否披露依据 | 未来三年利润高速增长 |

> **G 类处理原则**：不得简单判真或假，标记为「预测/假设/主观判断」，并核查是否披露依据。**v2.6.0 起**：每条 G 类主张必须标注「依据已披露（附证据编号）/ 依据未披露」；带"已无悬念/确定性强"等确定性措辞的预测按**预测事实化**进审计结论问题项（结论仍为观点或预测，不判真假）。

每条主张被结构化（含 `claim_id / entity / metric / value / unit / period / scope / currency / risk_level / source_location`），系统据此分别调用搜索、财务计算与矛盾检测。

### 5.2 确定性复算引擎（内嵌，亲自计算）

对数值类主张，智能体**不靠"感觉"，而是按公式重算**。有 shell 时调用 `skills/finproof-verification/bin/finproof_calc.py` 获得无误差十进制结果；**无 shell 时必须在主张卡标注〔心算估算，未经引擎复算〕**，并写出同类计算过程，并写出"公式 + 输入 + 结果 + 与原值差异"。

| 子命令 | 功能 |
|---|---|
| `convert` | 单位/币种换算为元（UNIT_SCALE） |
| `extract` | 从文本抽取结构化金融数值（千分位/括号负数/方向词符号） |
| `match` | 主张数值 vs 证据数值匹配（容差 0.1%） |
| `yoy` / `qoq` | 同比 / 环比增长率（±0.5pp） |
| `quarter` | 累计转单季推导（Q2=H1−Q1 / Q4=FY−Q1−Q2−Q3 …） |
| `margin` | 毛利率/净利率/费用率/业务占比 |
| `cagr` / `eps` / `roe` / `debt` / `cashdiff` | 复合增长/每股收益/净资产收益率/资产负债率/现金流差异 |
| `period` | 期间归一化（standalone vs cumulative） |
| `temporal` | **引用时序检查（v2.6.2）**：来源覆盖期间 vs 数据所属期间 → IMPOSSIBLE/COVERED/PARTIAL/UNCLEAR（"时序不可能"由模型语义判定收敛为确定性输出） |
| `sum_check` | **总和一致性（v2.8.0）**：分项之和 vs 合计（SOTP/成本明细/分部收入），相对容差 0.1% |
| `forecast_scan` | **预测事实化扫描（v2.8.1）**：确定性措辞 + 依据披露 → FLAG/CLEAN（把第一轮 E7 的执行不一致收敛为确定性输出） |
| `cite_check` | **引用真伪核验（v2.8.1）**：链接可达 / 摘录逐字命中 / 来源日期与数据期间一致（含 DOI 解析、离线快照、… 省略匹配） |

**演示高光**（报告称"Q2 收入 60 亿"，实为 H1 累计误当单季）：

```bash
python3 skills/finproof-verification/bin/finproof_calc.py quarter --h1 60 --q1 28
# → {"result": 32.0, "formula": "Q2 = H1 − Q1"}  → 结论：反驳
```

### 5.3 六类判定 + 八步决策链

每条主张走八步决策链：**证据 → 实体 → 指标 → 期间 → 口径 → 数值 → 语义 → 映射**。六类结论：

| Verdict | 中文 | 触发条件 |
|---|---|---|
| **SUPPORTED** | 支持 | 证据直接支持主张的主体/指标/期间/单位/口径/数值（允许正常舍入误差） |
| **REFUTED** | 反驳 | 证据给出冲突事实/错误数值/错误期间/错误单位/相反方向 |
| **PARTIALLY_SUPPORTED** | 部分支持 | 主张含多组成部分，部分成立但关键部分缺失 |
| **INSUFFICIENT_EVIDENCE** | 证据不足 | 现有证据既不能证明也不能反驳 |
| **OPINION_OR_FORECAST** | 观点或预测 | 预测/展望/主观判断，不判真假 |
| **UNABLE_TO_DETERMINE** | 无法判断 | 材料缺失或不可判定 |

> **边界铁律**：**REFUTED 优先于 PARTIALLY_SUPPORTED**。数值冲突（确定性复算否定）必须判 REFUTED，语义完整性再高也不得把 REFUTED 降级为 PARTIAL（数值冲突守卫 `guard_semantic_not_override_numeric`）。

### 5.4 九类错误分类（Error Taxonomy）

被反驳/部分支持的主张，按此体系归类：

| # | 错误类型 | 定义 | 高频触发点 |
|---|---|---|---|
| 1 | **数字错误** | 报告数字与原始文件不一致 | 抄写/录入偏差 |
| 2 | **计算错误** | 原始数字正确，但同比/环比/利润率/占比计算错 | 增长率公式用错基数 |
| 3 | **时间错误** | 使用错误年份/季度或过期信息 | 把去年同期当今年 |
| 4 | **口径错误** | 口径混用导致结论失真 | 单季↔累计、营收↔主营收入、归母↔净利润、调整前↔调整后、合并↔母公司、人民币↔港币/美元 |
| 5 | **引用错配** | 引用文件真实存在，但内容无法支持结论 | 断章取义、张冠李戴；**时序不可能**（v2.6.0：来源覆盖期间早于数据所属期间，纯逻辑即可判反驳，无需证据闭环） |
| 6 | **证据不足** | 报告给确定性判断，但材料只能部分/无法支持 | 缺原始披露佐证 |
| 7 | **跨文件矛盾** | 同公司不同文件/页面/版本数据冲突 | 多版本报告口径不一致 |
| 8 | **因果关系过度推断** | 两现象同时发生，报告却直接认定因果 | "毛利率升+原料降价"→"由原料降价推动" |
| 9 | **预测事实化** | 把预测/目标/预期写成既成事实 | "预计破百亿"→"已破百亿" |

> **口径错误（#4）是最高频雷区**：核验数字类主张时，必须显式核对单季/累计、合并/母公司、币种、调整前后。

### 5.5 证据检索与证据门（Evidence Retrieval Gate）

混合法（BM25 + 向量 + 规则 + 财务指标索引）召回原始披露，用 **strict scope** 避免"把对的证据误拒"。核心经验：**检索缺口是首要瓶颈**——正确证据没进候选池占失败案例的 81%，所以被判"证据不足"时先疑检索召回、再疑主张本身。

### 5.6 风险、审计与治理

- **风险公式**：`主张风险 = 错误可能性 × 业务影响程度 × 证据缺口`，分 `LOW / MEDIUM / HIGH / CRITICAL`。
- **高风险优先**：估值、收入、利润、增长率、重大合同、并购、监管处罚、诉讼、现金流、偿债能力、投资建议核心依据。
- **审计轨迹/回放**：每条结论可追溯到"证据 → 计算 → 判定依据"，可逐步复核。
- **红队与治理**：理解对抗样本、治理中心与知识图谱矛盾推理的评测口径。

### 5.7 范围判定门 + 需求判定门（Scope Gate & Web Verification）

**范围判定门（Scope Gate）——先问用户要哪种核验：** 是否联网由**用户要求**驱动，不由专家自定。受理时识别/询问用户：① **本地模式**（"仅按我上传的内容判断"，不联网）；② **联网模式**（"上传内容 + WorkBuddy 联网搜索核对真实披露"）。表述不清时开场问一句（不超过一次），并给默认建议（只发研报→建议联网模式；连源文件一起发→本地模式已很强）。未确认联网模式前绝不擅自联网。

进入**联网模式**后，智能体**优先调用 WorkBuddy 内置联网搜索（WebSearch / WebFetch）**检索交易所官网公告、公司 IR/年报原文、权威财经数据库等一手来源交叉验证——联网搜索是平台原生能力，**无需用户登录或连接任何外部服务**。

**首选：WorkBuddy 内置联网搜索（WebSearch / WebFetch）**——WebSearch 定位交易所官网/公司 IR/年报 PDF/权威财经库的一手链接，WebFetch 读取并提取同口径、同期间原始数值。金融数据 MCP（Tushare / 东方财富妙想 / 腾讯自选股）仅作**可选增强**：会话已连接时并用其结构化一手接口作二次交叉验证；未连接则完全忽略，不影响核验、不提示登录。

**需求判定门（Need Gate，仅联网模式）——先判断要不要联网：**

1. **本地证据能否覆盖全部主张？** 能 → 直接跳过联网。
2. **缺口是否确属外部/实时数据？** 只有"特定公司财报数字 / 最新行情 / 实时披露"才算"确需联网"。
3. **纯方法论 / 观点 / 历史科普类报告**，或证据已自洽的报告 → **永不触发联网**。
4. 确需联网 → 用 WorkBuddy 联网搜索补证；整个过程不向用户索要登录、不提示连接外部服务。

> 权威来源优先级：交易所公告/定期报告原文（一手）> 公司 IR > 权威财经数据库（Wind/东方财富/通联等）> 主流财经媒体（仅作线索）> 博客/论坛/社媒（不采用）。所有联网证据必须标注 `来源 + 数据时点`，并显式区分「本地证据」与「联网证据 / MCP 来源」。

## 六、报告级评分（FinProof Score，0–100）——**完全透明、可复算**

五维加权：

| 维度 | 权重 | 计算方式（简） |
|---|---|---|
| 可判定率（历史名「证据覆盖率」） | 25% | 闭环主张数 / 可判主张数 × 100 |
| 数字与计算准确性 | 25% | 100 − 数值错误率 × 100 × 2 |
| 引用一致性 | 20% | 100 − 引用错配率 × 100 × 2 |
| 来源权威性 | 15% | 加权平均证据等级分（S 级 100 / A 级 70 / 其他 40 / 未注明 0） |
| 时间与口径一致性 | 15% | 100 − (期间错配 + 口径问题) / 可判主张数 × 100 × 2 |

- 「可判主张数」= 总主张数 − 观点/预测类（G 类不计入分母）。
- 各维算到小数后一位，加权求和，**最后四舍五入到整数**。
- **完整规格（公式推导、惩罚系数来源、档位、主张级风险分算例、两份真实报告重算、六条边界）见 `skills/finproof-verification/references/scoring-spec.md`。**

**输出 Score 时必须一并给出（透明化硬要求）**：① 五维明细（原始观测 → 得分 → 加权贡献）；② 扣分清单（对应主张编号 + 错误类型 + 依据）；③ 档位；④ 固定警示（Score 反映证据链质量与引用规范，**不代表结论正确性**）；⑤ 自评声明（**专家自评，非第三方认证**）。

健康度统计随报告输出：主张总数 / 高风险数 / 数值错误数 / 证据不足数 / 引用错配数 / 口径问题数 / 已核验比例 / 未能判断比例。

**审计质量分 AQS（v2.7.0，与 FinProof Score 并列）**：FinProof Score 度量被审报告——好审计审烂报告反而得低分（实测 6 错全抓仅 71–72 分）；AQS 度量审计自身过程：主张覆盖 30% + 引擎复算率 25% + 证据可核性 20% + 复核完成度 15% + 链接复验率 10%，全机械可算，附五维明细与独立性警示。并列展示如 `FinProof Score 71/100 ‖ 审计质量 AQS 94/100`。

## 十、重要边界与操守（铁律）

- **不提供投资建议**：只做事实核验与证据审计。
- **检索/本地证据需你提供**：PDF 解析、向量检索不在专家运行环境内（专家指导如何做，不替代你提供原始披露文件）。联网核验依赖 **WorkBuddy 内置联网搜索（平台原生，无需你连接任何服务）**；金融数据 MCP 仅为可选增强。
- **不假装**：不伪装扫描件 OCR、多智能体编排、向量库/语义检索、自动生成修订版、大模型核验；不编造演示数据；无 Key 走带标识 Mock，不伪装为真实模型结果。**不伪装独立复核、不伪装链接复验**——没做就在报告里如实标注；自检复核〔机械层〕不得写成"已独立复核"；复核分歧照写，不静默采纳。
- **证据缺口先疑检索/联网，再疑主张**：被判"证据不足"时，先疑本地检索召回，再疑主张本身。
- **需求判定门**：是否联网、是否请用户登录，由报告内容决定，不是默认动作。
