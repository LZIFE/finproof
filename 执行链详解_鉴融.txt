鉴融——报告信息验证智能体
执行链详解：一次核验是怎么走完的

（本文描述智能体的实际执行顺序，每一步的输入、处理、输出与失败兜底。）


一、总览：十个步骤

步骤 0  受理
步骤 1  范围判定门（Scope Gate）—— 决定联网与否
步骤 2  文档解析 —— 拿得到文字吗
步骤 3  主张拆解 —— 拆成可核验单元
步骤 4  结构化归一化 —— 数字 / 期间 / 口径对齐
步骤 5  证据检索 —— 找得到原文吗
步骤 6  确定性复算 —— 算得对吗
步骤 7  八步判定链 —— 该判什么结论
步骤 8  联网补证 + 聚焦再搜索（仅联网模式）
步骤 9  评分与审计输出

每一步谁负责：
· 确定性程序（可复现、可测试）—— 解析、归一化、检索匹配、数值复算、评分
· 大模型（语义理解）—— 主张拆解、指标/期间识别、证据支持关系判断、因果与预测检测、修改建议

铁律：数字归程序，语义归模型。数值冲突不受语义判断影响。


二、逐步详解


步骤 0 · 受理

做什么：接收用户给的报告（文本或 PDF），识别待核验对象。
同时做：鼓励用户一并上传源文件（年报 / 公告 / 招股书）——本地证据越全，核验越强。
输出：待核验文档 + 本地证据集（若有）。


步骤 1 · 范围判定门（Scope Gate）—— 第一道门

做什么：判定本次是「本地模式」还是「联网模式」。
规则：
· 由用户要求驱动，专家不自定
· 表述不清时开场问一句（不超过一次），并给默认建议
  　只发研报 → 建议联网模式
  　连源文件一起发 → 本地模式已很强
· 未确认联网模式前，绝不擅自联网
输出：模式标记（本地 / 联网）。

为什么要这道门：联网与否涉及用户的数据边界与预期，不能由智能体自己拍板。


步骤 2 · 文档解析 —— 三级降级

做什么：把 PDF 变成带页码的文本块。
路径（依次尝试，前一级失败才降级）：
· 一级：pypdf / pdfplumber 文本直抽（文本型 PDF）
· 二级：PyMuPDF 渲染 150–300dpi PNG → 本机 tesseract -l chi_sim 中文识别（扫描件）
· 三级：多模态视觉逐页读取（无 shell 环境时）
· 表格：pdfplumber extract_table 恢复行列结构
复核：识别结果与上下文交叉验证（合计 = 分项之和、同比可复算），
　　　标注「OCR 识别，可能有 ±1 字符误差」。
仍失败（加密 / 损坏 / 手写级模糊）→ 标记 G4 提取失败，进入自核清单。
输出：带页码的文本块。

说明：这一级在早期工程版本是硬伤（原设计明令"不假装支持扫描件"）。
v1.4.1 起智能体自己走完 OCR 链路，不再把扫描件原样甩回用户。


步骤 3 · 主张拆解

做什么：把报告拆成相互独立、可核验的结构化主张。
怎么拆：规则初筛（数字 / 百分号 / 单位关键词）+ 模型语义拆解。
分类（A–G 七类）：
· A 原始数字 —— 直接陈述的数值
· B 计算型 —— 含同比 / 环比 / 比率等推导
· C 财务口径 —— 涉及单季 / 累计等口径
· D 业务事实 —— 定性业务结论
· E 因果关系 —— 归因型结论
· F 比较型 —— 同业 / 对标比较
· G 预测观点 —— 前瞻 / 主观判断
排序：高风险优先。
输出：主张列表，每条含报告原句、类型、风险等级。

为什么不整篇交给模型：整篇判断无法定位到具体哪句话错，也无法复算。


步骤 4 · 结构化归一化

做什么：把每条主张变成可比对的结构化字段。
归一化内容：
· 数字格式（万 / 亿 / % 统一）
· 单位与币种（人民币 / 港币 / 美元）
· 期间对齐（2025 年报 / 2025Q4 / 2026Q1）
· 口径识别（合并 vs 母公司、单季 vs 累计、归母 vs 净利润、调整前后）
输出：结构化主张（指标 code + 期间 + 口径 + 单位 + 币种 + 原值）。

这一级是高频事故区：口径混用（单季↔累计、营收↔主营收入、归母↔净利润）
不会报错，只会静悄悄地让结论失真，必须显式核对。


步骤 5 · 证据检索 —— 找得到原文吗

做什么：为每条主张找到对应的原始证据段落。
混合检索（多路召回 + 统一重排）：
· BM25 关键词（指标词 + 数值）→ 精确命中原文块
· 向量检索（语义近邻；无 Embedding 时降级为关键词 + 指标精确匹配，如实说明）
· 规则召回（公司 + metric_code + period 联合检索）
· 财务指标索引（从披露中重建结构化财务事实，供数值类主张直接比对）
证据门（Evidence Gate）：
· strict scope 归因 —— 从 metric_code 推断内在口径（归母 / 扣非），避免误拒正确证据
· 主表利润证据严格恢复 —— 归母 / 扣非两类指标按
  　公司 + 期间 + 指标 + 值 + 单位换算 + 披露舍入 严格重建验证窗口
· 输出 Top-N 候选（提交版默认 Top3 / Gate）
输出：带页码的证据候选块。

关键实测归因（Phase 23.37，21 个错误 case）：
· Retrieval failure 占 81%（17/21）
· Verification failure 仅 14%（3 条）
· Gold mismatch 5%（1 条）
· 16/21 的错误 case 中，正确证据根本没进 top10

结论：检索召回是绝对瓶颈，不是判定逻辑的瓶颈。
所以纪律是 —— 某主张被判"证据不足"时，先怀疑检索召回，再怀疑主张本身。
改进纪律（禁止项）：不修改 gold、不硬编码 case、不绕过 Gate、不调 reranker weight
（均已验证无效）。正确方向只有检索扩展：扩展 fact 覆盖、联合检索、query 分解。


步骤 6 · 确定性复算

做什么：对数值类主张亲自重算，不靠模型估算。
算什么（顺序）：
单位换算 → 币种换算 → 同比 / 环比 → 累计转单季 →
比率（毛利率 / 净利率 / 费用率 / 业务占比）→ CAGR / EPS / ROE / 资产负债率 / 现金流差异
非财务报告自动降级为通用数值复算（占比 / 增长率 / 总和一致性）。
怎么算：按 calc-engine.md 的公式与容差；有 shell 时调用 bin/finproof_calc.py
　　　　（Python decimal 精确十进制运算，避免浮点误差）。
输出：复算轨迹 —— 公式 + 输入 + 结果 + 与报告原值的差异。
容差策略：对舍入、四舍五入留合理容差，不因显示精度差异误判。


步骤 7 · 八步判定链

做什么：对每条主张依次走八个检查点，不跳步。
顺序：
1 证据 —— 证据可用性
2 实体 —— 公司 / 主体识别对不对
3 指标 —— 这个数字对应哪个指标
4 期间 —— 报告期是否对齐
5 口径 —— 单季 / 累计、归母 / 净利等是否混用
6 数值 —— 确定性复算结果
7 语义 —— 主张完整度、因果是否成立、是否预测
8 映射 —— 落到六类结论

数值守卫：第 6 步若冲突，直接判 REFUTED，受保护，不被第 7 步语义判断覆盖。
输出：六类结论之一 —— 支持 / 反驳 / 部分支持 / 证据不足 / 观点或预测 / 无法判断。
不强行二分：预测 / 假设 / 主观判断标记"观点或预测"，并核查是否披露依据，不判真假。


步骤 8 · 联网补证 + 聚焦再搜索（仅联网模式）

需求判定门（Need Gate，第二道门）：
· 先判：本地证据能否覆盖全部主张？
· 能覆盖 → 直接跳过联网，照常输出本地结论
· 不能覆盖，且缺口确属外部 / 实时事实（特定公司财报、最新行情、实时披露）→ 才发起联网
· 纯方法论 / 观点类报告、或证据已自洽的报告，绝不触发联网

联网怎么走：
· WebSearch 定位一手来源 → WebFetch 读取并提取
· 来源优先级：交易所公告 / 公司 IR / 年报原文 → 权威媒体 → 行业价格库 → 行情聚合
· 标注来源 URL + 抓取时间，显式区分「本地证据」与「联网证据」
· 平台原生能力，不索取登录、不提示连接外部 MCP

聚焦再搜索（首轮仍有缺口时的默认行为）：
· 换词：全称 ↔ 简称 ↔ 股票代码 ↔ 英文品名
· 换源：升级权威源（年报 PDF → 互动易 / IR → 权威媒体 → 行业价格库 → 行情聚合）
· 收窄：精确到具体期间
· 子公司：用"主要控股参股公司"段落定位
· 重试 ≤2–3 轮，每轮记录 query + 来源类型 + 命中情况
· 命中即收口复算；穷尽仍无 → 保留"证据不足"，并透明列出已尝试的检索

失败归因顺序：先疑检索召回 → 再聚焦再搜索 → 最后才疑主张本身。


步骤 9 · 评分与审计输出

评分：FinProof Score（0–100，五维加权）
· 证据覆盖率 25%
· 数字与计算准确性 25%
· 引用一致性 20%
· 来源权威性 15%
· 时间与口径一致性 15%
每条扣分必须可追溯到具体主张与理由，不做无解释的评分。

健康度统计：主张总数 / 高风险数 / 数字错误数 / 证据不足数 /
引用错配数 / 口径问题数 / 已核验比例 / 未能判断比例。

逐条主张卡（三栏）：
　报告原句 / 原始证据（含页码，或 URL + 抓取时间）/ 计算过程（公式 + 输入 + 结果）
另附：主张类型、风险等级、六类结论、修改建议、聚焦再搜索记录。

收口：G1–G4 缺口分类 + 「需用户自行核验清单」
· G1 源文件缺失 —— 用户未上传对应披露文件
· G2 检索不可达 —— 付费墙 / 未索引 / 离岸 / Pre-IPO 披露分散
· G3 非公开数据 —— 细分口径、子公司经营数据、内部假设
· G4 提取失败 —— OCR 已尝试仍不可信


三、一次真跑（某拟港股 IPO 简报，8 页 / 30 条主张）

步骤 1　用户选联网模式（非上市公司，公开披露少）
步骤 2　pypdf 直抽成功（文本型 PDF，8 页，个别断字空格但内容完整）
步骤 3-4　拆出 30 条主张，归一化期间与口径
步骤 5-6　本地复算：营收 CAGR 74.2%、增速 87.9%、IP 占比 56.7% 全部对上
步骤 7　逐条走八步判定链
步骤 8　本地证据不足 → 触发联网：
  　· 首轮 4 路检索（招股书 / 母公司 6-K / 同业年报 / 行业咨询）
  　· 2 处缺口未闭环 → 聚焦再搜索 2 路（经营现金流、分品类毛利率）→ 全部命中
  　· 命中后收口复算
步骤 9　输出：Score 94/100，30 条主张卡，抓出「自有 IP 占比 99.1%」的口径误用
　　　　（实为"自主产品"占比，纯自有约 90%）

一个值得讲的插曲：内部复算曾标记 3 个"疑点"——
IP 三类合计 34.88 ≠ 营收 35.87；糯米儿破 2 亿 vs 自有 IP 仅 1.99 亿；门店 323 ≠ 334。
外部来源全部解释清楚：潮玩产品占 97.2%（剩余非潮玩）、批发 ≠ 零售口径、11 家代理店。
三个都不是错误。这正是"先疑检索，再疑主张"的价值 ——
不冤枉报告，也不放过真问题。


四、失败与兜底

· 无 API Key → 走 Mock 模式，结果带"Mock 模式，非真实模型输出"标识，不伪装
· 无联网能力 → 如实说明，退回本地证据链，绝不假装已搜索
· 检索失败 → 不改 gold、不硬编码、不绕过 Gate、不调 reranker weight，只做检索扩展
· 扫描件识别不了 → 说明已尝试的 OCR 手段（渲染 dpi、语言包、是否视觉读取），归 G4 交回用户
· 仍不确定 → 判"无法判断"，不强行二分

设计取舍：宁可少做，不可假装。
覆盖率可以不是 100%，但每一个缺口必须透明、可追溯、可行动。
