一、整体框架

输入 → 门控 → 处理链 → 分级 → 输出。分级体系贯穿全程，与处理链正交。

  • 门控层：范围判定门由用户拍板（本地 / 联网）；需求判定门在本地证据够用时直接跳过联网
  • 处理链：主张拆解 → 证据检索 → 确定性复算 → 八步判定链
  • 分级体系：证据等级（来源多硬）与风险等级（错了多糟）彼此独立，同一条主张可同时标注

二、端到端核验流程

两道门决定「要不要联网」，聚焦再搜索让「证据不足」成为起点而非终点。

  • 虚线回流是核心：补证后重新判定，而不是一次搜不到就放弃
  • 聚焦再搜索：换词（全称/简称/代码/英文品名）+ 换源（年报 → IR → 权威媒体 → 行业库）再搜 2–3 轮，穷尽才收口
  • 数值守卫：复算对不上直接判 REFUTED，语义判断无权翻案

三、执行链十步

每一步由谁负责 —— 数字归程序，语义归模型。

  • 程序负责（可复现）：解析、归一化、检索匹配、数值复算、评分
  • 模型负责（语义）：主张拆解、指标/期间识别、证据支持关系、因果与预测检测
  • 步骤 4 口径归一化是隐形雷区：单季↔累计、归母↔净利润、合并↔母公司，不会报错只会让结论静悄悄地错

四、四层技术架构

四层分离 + 双保险判定。

  • 关键设计：数字走确定性引擎，语义走模型，两条链路互不覆盖
  • 证据获取层：文本直抽 → 渲染 OCR → 视觉读取 → 内置联网搜索，扫描件由专家自己识别
  • 缺口治理层：G1–G4 分类，汇总为「需用户自行核验清单」

五、证据检索：混合检索 + 证据门

四路召回保证「捞得全」，证据门保证「不误杀」。

  • 四路：BM25（关键词+数值）、向量（语义近邻）、规则召回（公司+指标+期间）、财务指标索引（结构化事实）
  • 证据门：strict scope 归因 —— 从 metric_code 推断归母/扣非口径，避免把对的证据判成不匹配
  • 无 Embedding 服务时向量路降级为关键词+指标精确匹配，如实说明，不假装做了语义检索
  • 实测归因：检索失败占 81%（17/21），其中 16/21 是正确证据根本没进 top10 —— 检索召回是绝对瓶颈
