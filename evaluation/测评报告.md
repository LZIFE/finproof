# 鉴融（FinProof）对比测评报告——专用报告审计框架 vs 通用 Agent 裸提示

日期：2026-10-24 · 裁判：主会话（持密钥盲评外的独立评分） · 全部原始输出存 `runs/`

---

## 一、测评设计

**问题**：同一份报告、同一份证据，"专门做报告审计的鉴融框架"与"通用 agent + 一句裸提示"（模拟在 ZCode / Claude Code 里直接说"帮我检查这个报告里的错误"）相比，能否检出更多问题、产出更可用的结论？

**材料**（`evaluation/` 目录，可复用）：
- `test_report.txt`：1 页商业分析深度点评（数字锚点取自真实披露），预埋 **9 处错误（E1–E9）+ 6 处正确表述（T1–T6）**。错误覆盖：同比计算错误、数字对调（超舍入豁免）、累计充单季、量级 ×10、引用期间错配、编造因果、预测事实化、SOTP 占比复算错、行业占比失实——其中 5 处标注"隐蔽度高"。
- `evidence_pack.txt`：5 份源文件摘录（年报/一季报/半年报/行情/行业数据），9 处错误全部可据其**客观判定**（裁判前经脚本复核数字自洽）。
- `ground_truth.json`：密钥（评分口径：检出 2 分 / 部分 1 分 / 未检出 0，满分 18；误报每处 −1）。

**分组**（同一基座模型 GLM-5.3、同一宿主 ZCode，隔离"框架"变量）：
- **基线组 ×2**：裸提示「请你帮我检查一下这个报告里面的错误、不属实的地方。」+ 两个文件路径。
- **鉴融组 ×2**：同一句用户请求 + 加载鉴融操作手册（SKILL.md）并按方法论执行（A–G 拆解、容差表、八步判定链、六类结论、对抗性五查），数值复算强制走确定性引擎 `finproof_calc.py`，本地模式。

**过程纪律**：第 1 轮基线因 agent 自行浏览目录读到了密钥而**作废重跑**（密钥随即移出目录）；该事件本身作为行为样本记录。

## 四、结论（如实）

1. **"检出更多"在本条件下不成立**：短报告 + 证据包齐全 + 强基座模型时，裸提示基线检出分 17/18（94%），鉴融 15/18（83%）；按"触及率"口径两组均为 9/9。鉴融少的 2 分不是漏检，而是判定哲学不同：它把预测归 G 类不判真假（E7）、把无法核对交回用户（E5）——其中 E7 鉴融未按自身规则点出"依据未披露"，属执行瑕疵，已记录为改进项。
2. **鉴融的真实差异化在被验证的四点**：
   - **可复算**：每条数值判定有引擎命令级溯源（基线是"看起来算了"）；
   - **可入库**：六类结论 + 五维评分 + 风险分级，两轮评分仅差 1 分（74/75），输出形态稳定可比较（基线两轮形态相似但无结构化锚点）；
   - **会排序**：CRITICAL 机制明确指出哪两处错误直接推翻"业绩高增/估值安全边际"的核心论点——基线把 9 条错误平铺，不告诉用户哪条致命；
   - **有边界**：缺口分类交回（G1 需补 p.12、需 2024 基数），且不越界读无关文件。
3. **对外表述建议**：不要说"别的 agent 查不出的错误我们能查出"（本数据不支持）；可以说——"同样的检查请求，鉴融把自由文本意见变成**可复算、可追溯、可入库**的审计结论：逐主张六类判定、每分可推导、并明确告诉你哪几处错误足以推翻核心论点、哪些需要补材料"。
4. **何时差距会拉开（下一轮设计建议）**：① 报告加长至 30+ 主张（基线注意力稀释，鉴融分批审协议生效）；② 无证据包的联网模式（鉴融的检索纪律/聚焦再搜索/来源定级发挥作用）；③ 基线换更弱/更省的模型（如 Flash 档）——真实"随手让 agent 看看"的场景；④ 近容差错误密度加大（0.1%–0.5% 区间）；⑤ 要求两次运行结论一致（可复现性）。本轮套件已具备，改参数即可复跑。

## 五、复现指南

1. 被测方给两个文件路径 + 一句话：「请你帮我检查一下这个报告里面的错误、不属实的地方。」（ZCode/Claude Code/任意框架通用）。
2. 跑鉴融方：加载 `~/.workbuddy/.../finproof-verifier/skills/finproof-verification/SKILL.md` 按其执行（提示词模板见 `runs/jianrong_run1_valid.txt` 头部）。
3. **评分前把 `ground_truth.json` 移出被测目录**（本轮教训：通用 agent 会浏览目录）。
4. 按 `ground_truth.json` 的评分口径打分；裁判不得为被测方。

# 第二轮：Flash 档对照（同一轻量模型上隔离"框架"变量）

**目的**：第一轮双臂都跑在强模型 GLM-5.3 上，基线被模型能力托底。第二轮把两臂都放到 **GLM-5.3-Flash**（轻量档，模拟日常随手用的快模型）——同模型同宿主，唯一变量是"裸提示 vs 鉴融方法论"。材料与密钥与第一轮完全相同。

**结果**（评分明细见 `runs/round2_flash_summary.txt`）：

| 臂 | 检出分/18 | 误报 | 产出 |
|---|---|---|---|
| Flash 裸提示 ×2 | 17 / 17 | 0 | 自由文本清单 |
| Flash + 鉴融方法论 ×2 | 17 / 16 | 0 | 结构化审计（评分 75/78·良，反驳清单与 GLM-5.3 档完全一致） |

**第二轮结论**：轻量档上检出同样打平（17 vs 17/16）——在"短报告 + 证据包齐全"的理想条件下，模型强弱对检出率影响不大，框架也不靠"多抓错误"取胜。**框架的稳定增益依旧且跨档成立**：①四个鉴融臂（跨两个模型档）反驳清单完全一致、评分 74–78 全落"良"档——输出可复现、可入库；②每条数值判定带引擎命令级溯源；③Flash 鉴融①甚至主动给出 N_e=12/19 的诚实覆盖率披露、"未复核"如实降级、#25 预测类附"依据未见披露 + 隐含 H2 需 6.87 亿"的量化提示——这些是裸提示不产出的信息。

**两轮合并的最终判定**：
1. "专门框架能检出通用 agent 查不出的错误"这一命题，在**证据齐全的短报告**条件下**不成立**（两档模型、八轮对照，基线 94%（17/18 × 4）vs 鉴融 83–94%，基本持平，唯一全灭的 E5 两边都只做对一半）。
2. 鉴融的差异化是**审计级产出**而非检出数：可复算（命令溯源）、可判定（六类结论/逐主张覆盖）、可量化（评分+风险+CRITICAL 承重分析）、可交付（G1–G4 缺口清单+未闭环≠通过）、行为可控（基线出现越界读文件的实测风险）。
3. 检出差距预期出现在**证据不齐全**的场景（无证据包/需联网定位一手来源/长报告注意力稀释）——那才是"通用 agent 直接说一句"真正失效的地方，也是第三轮建议的测法。

# 第三轮：长报告压力测试（35+ 主张 / 12 处预埋错误 / 8 个易误判陷阱）

**材料**：`test_report_long.txt`（51 条可拆解主张，含盈利预测表）+ `evidence_pack_long.txt`（新增扣非/加权股本/前三季/三费数据行）；密钥 `ground_truth_long.json`（E1–E9 同短报告，新增 E10 表内加总错、E11 正文-表格矛盾、E12 近容差费用率；T1–T8 为正确但易误判的陷阱，判错即误报）。全部数字经脚本复核自洽。

**结果**（GLM-5.3，各 1 轮）：

| 臂 | 检出分/24 | 误报 | 成本 | 亮点 |
|---|---|---|---|---|
| 裸提示基线 | **21** | 0 | 79k tok / 3.2 分钟 | 抓到 E10/E11/E12 与两处设计外真实不一致（表内 41.0 vs 正文 52.06、产能"翻倍"无据）；漏 E7（预测无依据未提） |
| 鉴融方法论 | **22** | 0 | 523k tok / 16 分钟 | 51 条主张全量编号判定、CRITICAL×5（增速/Q2/市值/占比/"接近全年"）、E7 与 E11 同句双问题分别捕获、**舍入豁免的精确应用**（#49 相对差 0.11%<0.5% 判支持，未误伤）、派生洞察（Q3 单季 0.386 亿→"逐季增强"证伪）、N_e=28/29、评分 74·问题项 24 |

**第三轮结论**：长报告下检出 22 vs 21，仍基本打平（强模型基线的注意力没有如预期稀释——35+ 主张仍全部覆盖）。鉴融的可展示优势依然是产出层：问题分级（哪 5 条 CRITICAL 推翻核心论点）、8 项 G1/G3 缺口交回清单、每条判定的引擎溯源、以及**该放过的精确放过**（舍入豁免、EPS 加权口径、表内自洽项零误伤）。

# 三轮总结（v2.6.0 前的阶段性总结，后续见第四/五轮与五轮总览）

| 场景 | 基线 | 鉴融 | 判定 |
|---|---|---|---|
| 短报告+证据包（GLM-5.3，×2） | 17/18 | 15/18 | 打平（鉴融判定哲学更保守） |
| 短报告+证据包（Flash，×2） | 17/18 | 17/16 | 打平 |
| 长报告+证据包（GLM-5.3，×1） | 21/24 | 22/24 | 打平（鉴融略优） |

1. **检出率不是差异化卖点**（三轮 10 轮，88–94% vs 83–94%）——在证据包齐全、报告结构清晰的条件下，强/轻量模型的裸提示都能抓到绝大部分预埋错误。
2. **差异化（全部实测成立）**：①输出可复现可入库（鉴融 5 轮反驳清单跨模型档一致、评分 74–78）；②每条判定可复算（引擎命令）；③问题会分级（CRITICAL 指向推翻核心论点的错误）；④缺口会交回（G1–G3 清单+"未闭环≠通过"）；⑤该放过的精确放过（舍入豁免/口径对照零误伤）；⑥行为有边界（基线出现越界读文件的实测风险）。
3. **对外口径建议**："同样一句话，把自由文本意见变成可复算、可追溯、可入库、会排序的审计结论"，而非"查出别人查不出的错误"。
4. **若仍要证明"检出更多"**：需构造"无证据包+联网检索一手来源"场景（E1/E2/E4/E6/E9 类错误在无证据时基线无法闭环，鉴融的检索纪律与来源定级才是独占能力）——**已执行，见下第四/五轮**。
