# 确定性财务计算引擎（calc-engine，内嵌于专家自身）

> 来源：`backend/app/services/verification/financial_value.py`、`growth_verifier.py`、`period_verifier.py`、`numeric_verifier.py`、`base.py`、`period_context.py`、`metric_scope.py`。
> 本文件把 FinProof 后端**确定性计算逻辑**编码为专家可直接执行的规则。专家在对话中按这些公式与容差**亲自复算**每条数值类主张，而非仅描述"应当如何算"。

## 一、单位换算表（UNIT_SCALE，统一换算为"元"或百分比）

| 单位 | scale（×元） |
|---|---|
| 元 | 1.0 |
| 千元 | 1e3 |
| 万元 | 1e4 |
| 亿元 / 万万元 | 1e8 |
| 百万 / million / mb | 1e6 |
| 十亿 | 1e9 |
| 百亿 | 1e10 |
| billion / b | 1e9 |

- 英文单位（million/billion/mb/b）默认币种 **USD**；中文单位默认 **CNY**；无单位时由上下文回填。
- 百分比类型：`%`=percentage，`百分点/个百分点`=percentage_point，`bp/basis points`=basis_point（比较时用差值而非比值）。
- 千分位：`1,234.56` / 全角逗号 `，` / 顿号 `、` 均视为分隔符，先剥离再解析。
- 负数表示：`-1.08`、`(1,081,776)` 括号负数、`同比下降/亏损扩大/减少/降低` 标记为负方向（yoy_decline）。

## 二、数值匹配与容差（唯一权威口径）

- **绝对数值/累计转单季容差 `VALUE_TOLERANCE = 0.1%`**（相对容差；Phase 23.7 由 0.5% 收紧到 0.1% 以消除假阳性支持）。
- **增长率容差 `GROWTH_TOLERANCE_PP = 0.5` 个百分点**。
- 匹配前先按 **metric + period + unit + scope + source_span** 综合绑定，**不简单取证据中第一个数字**；多数字歧义时优先选 metric/period 匹配且带单位的数值。
- 匹配比较方式：换算为"元"后比相对误差；百分比/百分点直接比数值。

**披露舍入豁免（唯一例外，上限 0.5%）**：偏差若**能由报告声明的舍入精度解释**（亿元保留两位、万元取整等），可判 SUPPORTED 并标 `[舍入差异 x%]`；**超过 0.5% 一律 REFUTED**，无论能否用"舍入"解释。

**输出纪律**：任何数值主张**无论判定通过与否**，都必须写出 `复算值 / 报告值 / 绝对差 / 相对差%`——只看"匹配/不匹配"会漏掉明细级问题（对抗性防御硬要求）。

> 本节容差是**全包唯一口径**。其他文件（含 `adversarial-blindspots.md`）的阈值均以此为准；如出现不一致，以本节为准并立即修正该文件。

## 三、核心公式（专家亲算）

### 3.1 同比增长率（YoY）
```
同比增长率(%) = (本期值 − 上年同期值) / 上年同期值 × 100%
```
- 证据需同时给出**本期**与**上年同期**同口径数值；用子期间（如 Q1）数据对验证全年（FY）增长率会错配 → 拒绝。
- 计算值在主张值 **±0.5pp** 内 → 支持；明显偏离 → 反驳；缺当期/去年同期数值 → 证据不足。

### 3.2 环比增长率（QoQ）
```
环比增长率(%) = (本期值 − 上一期值) / 上一期值 × 100%
```
（公式同 YoY，基期改为相邻期间。）

### 3.3 累计转单季（口径还原，MVP 核心卖点）
```
Q1 = Q1（直接披露）
Q2 = H1 − Q1
Q3 = Q3（直接披露，或 H1−H1? 不适用）
Q4 = FY − Q1 − Q2 − Q3        // 全年 − 前三季度
H1 = Q1 + Q2
FY = Q1 + Q2 + Q3 + Q4
```
- 演示高光：`报告称"第二季度收入 60 亿"`，若证据 H1=60、Q1=28 → `Q2 = 60 − 28 = 32 亿`，判定**反驳**（把半年度累计误当单季）。
- 容差 ±0.1%。

### 3.4 毛利率 / 净利率 / 费用率
```
毛利率(%)     = (营业收入 − 营业成本) / 营业收入 × 100%
净利率(%)     = 净利润 / 营业收入 × 100%
费用率(%)     = 某项费用 / 营业收入 × 100%
业务收入占比(%) = 某业务分部收入 / 总营业收入 × 100%
```

### 3.5 CAGR（复合年均增长率）
```
CAGR(%) = (末期值 / 初期值)^(1 / 年数) − 1 ，再 ×100%
```

### 3.6 每股收益 / ROE / 资产负债率 / 现金流差异
```
EPS              = 净利润 / 总股本
ROE(%)           = 净利润 / 平均净资产 × 100%
资产负债率(%)    = 总负债 / 总资产 × 100%
经营现金流−净利润 = 经营活动现金流净额 − 净利润（差异异常需提示）
```

### 3.7 单位 / 币种换算
- 亿元↔万元：`1 亿元 = 10000 万元`；元↔亿元：`1 亿元 = 1e8 元`。
- 币种：CNY / HKD / USD 必须显式区分并标注；混用即口径错误。

## 四、期间归一化（PeriodContext）

标准期间格式：`YYYYFY`（年报/全年）、`YYYYH1`/`YYYYH2`（半年报）、`YYYYQ1–Q4`（季报）；中文"中报/半年度→H1""第一季度→Q1"等。
- 区分 **standalone（单季）** vs **cumulative / ytd（累计）**：累计值不可直接当单季值。
- 同比基期：`上年同期 / 去年同期 / 同比` → 上一会计年度同期间。
- 推导：单季缺失时用累计减已披露单季（见 3.3）。

## 五、口径归因（metric_scope，strict scope）

- 从 `metric_code` 推断 intrinsic scope：**归母** vs **扣非** 净利润必须区分；验证前用同一 scope 语义，避免误拒正确证据。
- `net_profit_attributable` / `deducted_net_profit` 两类须严格按 company+period+metric+value+单位换算+披露舍入重建验证窗口，排除扣非混淆。

## 六、专家执行纪律

1. 收到数值类主张，先解析：剥离千分位 → 识别单位/币种/符号/期间 → 换算为可比基准（元或百分比）。
2. 仅当证据给出**同 metric + 同 period + 同 scope + 同 unit** 的可比数值时才复算；否则标"证据不足"，不要硬算。
3. 复算一律写出**公式 + 输入 + 结果 + 与报告原值差异**，让用户可逐步核对（对应审计轨迹）。
4. 数值冲突（复算否定）→ 直接 REFUTED，不被任何语义判断覆盖。
5. 非数值类（业务事实/因果/比较/预测）→ 路由到语义核验，不强行做数值匹配（避免误判 UNABLE）。
6. 所有 rounding/单位/币种/口径处理必须显式，禁止"看着差不多"。
