鉴融——报告信息验证智能体

整体流程与架构 · v1.5.0

一、端到端核验流程

  • 范围判定门：本地 / 联网由用户定，专家不自定；需求判定门仅在联网模式生效，本地证据足够则跳过检索
  • 聚焦再搜索：「证据不足」是起点不是终点 —— 换词（全称/简称/代码/英文品名）+ 换源（年报 → IR → 权威媒体 → 行业库）再搜 2–3 轮，穷尽才收口，逐轮记录
  • 数值冲突受守卫保护：复算对不上直接判「反驳」，不被语义判断覆盖

二、四层技术架构

  • 关键设计：数字走确定性引擎，语义走模型，两条链路互不覆盖 —— 数字不会因为模型「感觉像」就放过
  • 证据获取层：pypdf/pdfplumber 直抽 → PyMuPDF 渲染 → tesseract 中文 OCR → 多模态视觉读取 → 内置 WebSearch，扫描件由专家自己识别，不再甩回用户
  • 缺口治理层：G1 源文件缺失 / G2 检索不可达 / G3 非公开数据 / G4 提取失败，汇总为「需用户自行核验清单」

三、核心方法论

  • 主张拆解 A–G 七类 —— 原始数字 / 计算 / 财务口径 / 业务事实 / 因果关系 / 比较 / 预测观点，先拆解再判定，不把整篇交给模型
  • 九类错误 —— 数字、计算、时间、口径、引用错配、证据不足、跨文件矛盾、因果过度推断、预测事实化
  • 六类结论 —— 支持 / 反驳 / 部分支持 / 证据不足 / 观点或预测 / 无法判断
  • 八步判定链 —— 证据 → 实体 → 指标 → 期间 → 口径 → 数值 → 语义 → 映射，每步不跳
  • FinProof Score（0–100）—— 证据覆盖率 25% · 数字与计算准确性 25% · 引用一致性 20% · 来源权威性 15% · 时间与口径一致性 15%，每条扣分可追溯到具体主张

四、实测与边界

  • 某拟港股 IPO 简报（8 页 / 30 主张）：Score 94/100，抓出同业龙头「自有 IP 占比 99.1%」的口径误用（实为「自主产品」占比，纯自有约 90%）
  • 某 A 股研报（17 主张 / 聚焦再搜索策略对照）：覆盖率 82% → 100%，缺口 3 → 0，Score 85 → 89
  • 边界：检索是首要瓶颈（付费墙 / 未索引来源）· OCR 非万能（手写、低清扫描件可能出错）· 语义归因仍靠模型 · 只报错不改稿

不追求虚假的 100% 覆盖 —— 让每一个缺口透明、可追溯、可行动。
