# FinProof Score 评分规格（完全公开、可复算）

> 本文件是鉴融打分的**唯一权威口径**。任何一次输出 FinProof Score，都必须按本文件的公式计算，并附上第七节要求的明细。
> 目的：**让分数的每一个数字都能被用户自己重算出来。** 不接受"经验打分"、不接受无推导的分数。

---

## 一、透明化三原则

1. **可复算**：给定主张清单与判定结果，任何人都能按公式算出同一个分数。
2. **可归因**：每一分的扣除都能指向**具体主张编号 + 具体理由**，不接受"整体感觉"。
3. **自评声明**：这是**专家自评分**，不是第三方认证分。输出时必须声明。

---

## 二、统计口径（先把分母定清楚）

| 概念 | 定义 | 说明 |
|---|---|---|
| **总主张数** `N` | 拆解出的全部结构化主张 | 含观点/预测类 |
| **可判主张数** `N_d` | `N` − 观点/预测类(G 类) | **G 类不计入任何分母**（无从判真假） |
| **闭环主张数** `N_c` | 有证据可判（支持/反驳/部分支持/无法判断） | 不含"证据不足" |
| **数值类主张数** `N_v` | A/B/C 三类（含数字或计算的主张） | 数值准确性的分母 |
| **数值类错误数** `E_v` | 数值类中判 REFUTED 的条数 | |
| **引用错配数** `E_q` | 来源与页码/章节/报告期不对齐的条数 | |
| **期间错配数** `E_p` | 用错期间（去年同期当今年、单季当累计等） | |
| **口径问题数** `E_s` | 归母↔扣非、营收↔主营、单季↔累计、合并↔母公司、币种混用 | |
| **证据不足数** `E_i` | 判 INSUFFICIENT 的条数（含 G1–G4） | |

## 三、五维打分公式

### 3.1 可判定率（权重 25%，历史名「证据覆盖率」）

```
可判定率 = N_c / N_d × 100
```
- 闭环 = 有证据支撑判定；「证据不足」**不计入闭环**。
- 联网模式下须先完成聚焦再搜索，穷尽后才可把该主张算作未闭环。
- **更名说明（v2.5.0）**：本维历史名为「证据覆盖率」，但闭环口径含支持/反驳/部分支持/无法判断——衡量的是"能否判定"而非"证据是否充分"，名实不符。现更名为**可判定率**；**公式、权重、口径、全部历史分数不变**，历史报告中读到「证据覆盖率」即本维。

### 3.2 数字与计算准确性（权重 25%）

```
错误率 = E_v / N_v
准确性 = max(0, 100 − 错误率 × 100 × 2)
```
- **惩罚系数 = 2**：数值错误的破坏力大于其他瑕疵，按 2 倍扣。
- `N_v = 0`（纯定性报告）→ 该维按 **80** 计（无从检验，不给满分也不清零），并在明细中注明。

### 3.3 引用一致性（权重 20%）

```
错配率 = E_q / N_d
引用一致性 = max(0, 100 − 错配率 × 100 × 2)
```
- 引用错配 = 来源真实但**支撑不了该主张**（张冠李戴、期间不对应、用行业数据论证公司结论）。
- 引用本身存在但页码/章节/报告期任一缺失 → 计入错配。

### 3.4 来源权威性（权重 15%）

```
来源权威性 = Σ(每条闭环主张所用最高证据等级分) / N_c
```
| 证据等级 | 分值 | 典型来源 |
|---|---|---|
| **S 级** | 100 | 交易所公告、定期报告（年报/中报）、招股书、监管文件、审计报告、法院或政府正式文件 |
| **A 级** | 70 | 公司官网、投资者关系材料、业绩说明会、公司公告性新闻稿 |
| **其他来源** | 40 | 权威财经媒体、第三方研究机构、行业协会、政府统计年鉴 |
| **未注明来源** | 0 | 报告未给出来源或来源不可追溯 |

> 之前的版本只定义了 S / A 两级，"其他来源"无档位，导致这一维**无法计算**。本版补齐四档，使该维度可复算。
> 每条主张取**最高等级**的证据，不重复计分。

**弱来源披露（v2.5.0 起硬规则，不改分数、只加警示）**：当闭环主张所用证据中 **S+A 级占比 < 50%**，或本维得分 **< 60** 时，报告健康度的证据等级分布处**必须**附显著警示行——「⚠ 弱来源依赖：S+A 级证据占比 X%（x/y），本报告结论可靠性受限，建议补充交易所/定期报告等一手来源」。只警示、不降分（权重 15% 是既有校准口径），但不得隐去。

### 3.5 时间与口径一致性（权重 15%）

```
问题率 = (E_p + E_s) / N_d
时间与口径一致性 = max(0, 100 − 问题率 × 100 × 2)
```

## 四、总分公式

```
FinProof Score = 0.25 × 可判定率
               + 0.25 × 准确性
               + 0.20 × 引用一致性
               + 0.15 × 来源权威性
               + 0.15 × 时间与口径一致性
```

**取整规则**：各维先算到小数后一位，加权求和，最后**四舍五入到整数**。（先各自取整再加权会产生累积误差，禁止。加权求和时使用**未取整的各维分值**；展示时各维得分保留一位小数、加权贡献保留两位小数——表中 13.89、13.00 等即按未取整分值加权而来，用一位小数展示值相乘会差 ±0.01，属展示舍入，不是算错。）

**校验**：权重之和 = 100%，缺失维度不得跳过（`N_v=0` 时按 3.2 的兜底值）。

## 五、分数档位

| 档位 | 区间 | 含义 | 附加要求 |
|---|---|---|---|
| 优 | 90–100 | 证据链完整，无实质性问题 | 若仍有 REFUTED，**摘要首行必须点名该矛盾** |
| 良 | 75–89 | 个别瑕疵，不影响核心结论 | 列出瑕疵条数 |
| 一般 | 60–74 | 存在影响局部结论的问题，需修订 | 给出修订优先级 |
| 差 | <60 | 存在影响核心结论的问题，不建议直接使用 | 必须列出所有 REFUTED 与影响核心结论的缺口 |

**档位行强制格式（v2.5.0 起；v2.6.0 增预测事实化计数）**：任何档位结论必须写成——`{{分数}} / 100 · {{档位}}——问题项 {{N}} 条（反驳 x / 证据不足 x / 部分支持 x / 无法判断 x / 预测事实化 x）；分数衡量证据链质量与引用规范，不代表结论正确性`。**分数高 ≠ 报告正确**：一份含 REFUTED 的报告仍可能得高分，档位行的问题项计数就是为了让读者不脱离问题清单单看分数。预测事实化条目为 G 类标记性问题项（确定性措辞、依据未披露），**不计入评分分母**、只计入问题项计数（口径见 `SKILL.md` §一 G 类输出纪律）。

## 六、主张级风险分（与总分是两套，勿混用）

```
risk_score = 基准分 + 重要性 + 置信度项 + 证据质量项 + 预测加分
           → clamp 到该结论的区间
```

### 6.1 基准分（按结论取区间中值）

| 结论 | 区间 | 基准分 |
|---|---|---|
| REFUTED | 80–100 | 90 |
| INSUFFICIENT / UNABLE | 60–90 | 75 |
| PARTIALLY_SUPPORTED | 40–70 | 55 |
| SUPPORTED | 0–20 | 10 |
| 未知状态（兜底） | 30–60 | 45 |

### 6.2 四个调整项

| 调整项 | 算法 | 说明 |
|---|---|---|
| **重要性** | HIGH `+8` / MEDIUM `+4` / LOW `+0` | 优先取主张自带 risk_level；无则按类型推（数值类→HIGH） |
| **置信度** | `(confidence − 0.5) × 24` | REFUTED/INSUFFICIENT/UNABLE **只加不减**（高置信=风险确认）；SUPPORTED **只减不加**（高置信=风险缓解） |
| **证据质量** | 数值类核验 `eq=1.0`、语义类 `0.6`、其他 `0.3` | REFUTED：`(eq−0.6)×12`；INSUFFICIENT/UNABLE：`max((0.6−eq)×12, 0)` |
| **预测类** | `+15` | 仅当主张确为 FORECAST 类（含"预计/将/展望"等前瞻语态），**不得因指标名含"增长率"就判预测** |

### 6.3 等级映射

| 等级 | 条件 |
|---|---|
| **CRITICAL 极高** | `risk_score ≥ 90` **且** 该主张是核心结论的直接承重依据（投资建议/核心估值/收入利润主指标）——须显式写出判定理由 |
| **HIGH 高** | `risk_score > 65` |
| **MEDIUM 中** | `30 ≤ risk_score ≤ 65` |
| **LOW 低** | `risk_score < 30` |

> 说明：CLI/引擎只输出前三级的分数映射；**CRITICAL 是"引擎分 + 业务承重判断"的联合判定**，属于专家判断层，必须写明理由，不得只给标签。

### 6.4 报告整体风险

```
整体风险 = 0.5 × max(各主张 risk_score) + 0.5 × mean(非 SUPPORTED 主张的 risk_score)
```

## 八、完整算例（用真实跑过的两份报告重算）

### 算例 A：某 A 股上市公司研报（17 条主张，联网模式，含聚焦再搜索）

统计：`N=17`，其中 G 类观点/预测 `2` 条 → `N_d=15`；`N_c=15`（聚焦再搜索后缺口清零）；`N_v=9`；`E_v=2`；`E_q=0`；`E_p=0`；`E_s=1`。
证据等级分布：S 级 12 条、A 级 2 条、其他 1 条。

| 维度 | 计算 | 得分 | 加权 |
|---|---|---|---|
| 可判定率 | 15 / 15 × 100 | 100.0 | 25.00 |
| 数字准确性 | 100 − (2/9 × 100 × 2) = 100 − 44.4 | 55.6 | 13.89 |
| 引用一致性 | 100 − (0/15 × 100 × 2) | 100.0 | 20.00 |
| 来源权威性 | (12×100 + 2×70 + 1×40) / 15 = 1380/15 | 92.0 | 13.80 |
| 时间与口径 | 100 − ((0+1)/15 × 100 × 2) = 100 − 13.3 | 86.7 | 13.00 |
| **总分** | 25.00+13.89+20.00+13.80+13.00 | | **85.69 ≈ 86（良）** |

**重要说明**：本报告此前给出的自评分为 89，但**当时没有可复算的公式**（"来源权威性""时间与口径"两维为经验打分）。按本文件公开公式重算同一份数据得 **86**。差异来源就是"把隐含的打分标准显式化"——这正是透明化的价值：**旧分数不可复算，新分数可复算。今后所有分数一律按本公式给出。**

### 算例 B：某拟港股 IPO 商业分析简报（30 条主张，联网模式）

统计：`N=30`，其中 G 类 `3` 条 → `N_d=27`；`N_c=27`；`N_v=18`；`E_v=1`（股份支付 2.27 vs 证据 2.37，相对差 4.2%）；`E_q=0`；`E_p=0`；`E_s=1`（"自有 IP 占比 99.1%"实为"自主产品"口径）。
证据等级：S 级 20 条、A 级 5 条、其他 2 条。

| 维度 | 计算 | 得分 | 加权 |
|---|---|---|---|
| 可判定率 | 27 / 27 × 100 | 100.0 | 25.00 |
| 数字准确性 | 100 − (1/18 × 100 × 2) = 100 − 11.1 | 88.9 | 22.22 |
| 引用一致性 | 100 − 0 | 100.0 | 20.00 |
| 来源权威性 | (20×100 + 5×70 + 2×40) / 27 = 2430/27 | 90.0 | 13.50 |
| 时间与口径 | 100 − (1/27 × 100 × 2) = 100 − 7.4 | 92.6 | 13.89 |
| **总分** | 25.00+22.22+20.00+13.50+13.89 | | **94.61 ≈ 95（优）** |

> 该报告此前自评 94，按公开公式重算为 95。档位仍为「优」——**但因存在 1 条 REFUTED（股份支付）与 1 处口径问题，摘要首行必须点名**（第五节"优"档的附加要求）。

## 九、主张级风险分算例

**例**："2026Q1 营业收入同比增长 20%"，复算实际 15% → REFUTED，confidence = 0.9，数值类核验（eq = 1.0），重要性 HIGH。

| 步骤 | 计算 | 累计 |
|---|---|---|
| 基准分（REFUTED） | (80+100)/2 | 90 |
| 重要性 HIGH | +8 | 98 |
| 置信度 0.9 | (0.9−0.5)×24 = +9.6 | 107.6 |
| 证据质量（eq 1.0） | (1.0−0.6)×12 = +4.8 | 112.4 |
| clamp 到 [80,100] | 上限截断 | **100** |
| 等级 | 100 > 65 → HIGH；若该增长率为投资建议的直接承重依据 → 升 CRITICAL | **HIGH / CRITICAL** |

**对照**：一条 SUPPORTED 主张：基准 10 + 重要性 MEDIUM 4 = 14，置信度只减不加 → 14 → **LOW**。

## 十、校准依据（这个评分体系凭什么可信）

评分体系的有效性来自**金标准评测**，不是自我感觉。以下是真实跑出的数据（Phase 23.11 Gate，43 条金标准主张）：

| 指标 | 实测 | 目标 | 结论 |
|---|---|---|---|
| 端到端 Accuracy | **0.7442** | ≥0.70 | 达标 |
| Macro-F1 | **0.7264** | ≥0.60 | 达标 |
| Coverage | **0.7442** | ≥0.65 | 达标 |

分结论 F1（**含弱项，如实公开**）：

| 结论 | F1 |
|---|---|
| OPINION_OR_FORECAST | 1.00 |
| SUPPORTED | 0.88 |
| REFUTED | 0.71 |
| UNABLE_TO_DETERMINE | 0.67 |
| PARTIALLY_SUPPORTED | 0.67 |
| **INSUFFICIENT_EVIDENCE** | **0.43（最弱项）** |

**错误召回率的口径缺口（v2.5.0 补充披露）**：设计目标含「错误召回率 ≥90%」，但提交评测**只公布了 per-class F1（REFUTED 0.71），未公布、也未随包留存错误召回率（recall）**。F1 由精确率与召回率共同构成，**不得用 F1 暗示召回达标**。在校准数据补齐前，错误召回率一律按**未验证**表述。

**最弱项说明**：`证据不足` 的识别最不准——主因是检索召回缺口（错误归因中 Retrieval failure 占 **81%**，其中 16/21 是正确证据未进候选池）。这直接解释了为什么"聚焦再搜索"和"G1–G4 缺口分类"是本体系的关键设计：**它知道自己最弱的地方在哪，并把这一点告诉用户。**

> 诚实边界：以上为**内部金标准**（1 家真实公司 + 预埋 8–12 处已知错误的研报）上的评测，样本量有限（43 条），**不等于在所有报告上的表现**。不得对外表述为"通用准确率 74%"。

## 十一、边界与局限（必须随分数一起被告知）

1. **自评性质 + 独立复核层（v2.5.0 起）**：评分者是专家本人，被评的是专家自己整理的证据链。v2.5.0 起判定结论须经**独立复核**（异源模型盲复核优先，见 `independent-review.md`）——复核**降低**单模型误判风险，但**不改变自评性质**：分数仍非第三方认证，复核分歧如实披露而非静默采纳。
2. **不可跨报告强比较**：不同报告的主张构成不同（分母不同），85 分与 88 分的差异**不必然代表质量差异**。跨报告比较只在同一份报告的**版本前后对比**时才有意义。
3. **clamp 抹平区分度**：主张级 `risk_score` 在 clamp 后，5% 的偏差与 80% 的造假可能落在同一档。因此**主张卡的"相对差%"比风险分更能反映严重性**——两者都要给。
4. **`N_v=0` 的兜底是约定值**：纯定性报告的数字准确性按 80 计，这是为了避免"无从检验就给满分"或"直接清零"，属于设计约定，不是测量结果。
5. **引用规范 ≠ 结论正确**：引用一致性 20% + 来源权威性 15% 衡量的是**引用好不好看**，不是**结论对不对**。一份引用规范但数字有误的报告可能得分偏高——固定警示就是为了对冲这一点。
6. **两处仍属专家判断**：CRITICAL 等级判定（是否"承重"）、语义/因果类结论（无确定引擎兜底）。这两处无法纯公式化，必须写明理由。
7. **端到端复现性（v2.5.0 新增披露）**：**数值复算由确定性引擎执行，可复现**；但主张拆解、语义判定、证据定级由模型产出，**两次运行可能不同**——本报告依据当次运行快照（基本信息中的模型、模式、时间）。复跑同一报告，分数允许合理波动，波动主因是拆解与语义判定，不是公式。

## 十一、审计质量分 AQS（v2.7.0 起，与 FinProof Score 并列）

FinProof Score 度量**被审报告**（REFUTED 越多扣分越多，好审计审烂报告会得低分——实测悖论）；AQS 度量**审计自身的过程质量**，五维全部机械可算：

```
C 主张覆盖   = 已判定主张 / 全部拆解主张 × 100                权重 30%
E 引擎复算率 = N_e / N_v × 100（N_v=0 时按 80 计）            权重 25%
V 证据可核性 = 四必填完整的问题项 / 全部问题项 × 100          权重 20%
R 复核完成度 = 异源 100 / 同源盲复核 80 / 自检复核〔机械层〕60 / 未复核 0   权重 15%
L 链接复验率 = 已复验 URL / 全部联网证据 URL × 100            权重 10%
AQS = 0.30C + 0.25E + 0.20V + 0.15R + 0.10L（四舍五入取整）
本地模式：L 不适用，AQS = (0.30C + 0.25E + 0.20V + 0.15R) / 0.90
```

**算例（76 分报告的审计自身）**：C=9/9=100 · E=3/4=75 · V=4/4=100（含 #7 依据未披露如实标注） · R=100（异源+自检） · L=3/3=100 → AQS = 30+18.75+20+15+10 = **93.75 ≈ 94（优）**。并列展示：`FinProof Score 76/100 · 良 ‖ 审计质量 AQS 94/100 · 优`——"报告一般、审计优秀"从此一眼可辨。

**输出硬要求**：五维明细（分子/分母→得分→加权贡献）随 AQS 一并输出；**固定警示（逐字）**："AQS 衡量审计过程质量，FinProof Score 衡量被审报告的证据链质量——两分独立解读，不可互相替代（好审计审烂报告 = AQS 高 + FinProof 低，属正常且正确的组合）。"

**边界**：AQS 不度量判定的**正确性**（那需要外部金标准，属测评而非自评）；它度量审计过程的**完备与诚实程度**。五维全部来自审计自身的元数据，可机械复核。
